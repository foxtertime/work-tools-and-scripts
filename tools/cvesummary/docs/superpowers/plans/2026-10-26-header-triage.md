# Триаж в баре шапки — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Показать растриаженную долю каждого сегмента бара шапки.

**Architecture:** Правило триажа живёт в `roles.js`. При отрисовке шапки
считаем подходящие строки внутри каждого существующего сегмента и задаём
ширину слоя с диагональными тёмными полосами через CSS-переменную.

**Tech Stack:** Существующие Python, JavaScript и CSS, без новых зависимостей.

**Spec:** Требования пользователя в этой сессии: только бар шапки;
растриажено = (`Разработчик = SecOps` и `Принятая мера = Закрыто SecOps`)
или `Исполнитель = УА`; подсказка показывает всего и растриажено в сегменте.

## Global Constraints

- Сравнения без учёта регистра и лишних пробелов, как остальные роли.
- Статус задачи не входит в условие триажа; совпадение обоих условий даёт одну задачу.
- Сохраняем разбиение сегментов и размещение каждой задачи по первому основанию.
- Штриховка занимает точную долю сегмента слева, остаётся под текстом.
- Работа в существующей `feature/cvesummary-header-counters`; версии и changelog по CLAUDE.md.

## Review Focus

- Только одно поле SecOps заполнено — задача не растриажена.
- Исполнитель УА подходит независимо от остальных полей и статуса.
- Нет нужных необязательных колонок — триаж не определяется ошибочно.
- Доли 0%, частичная и 100%; оба условия не удваивают число.
- После resize подписи и тултипы работают, остальные бары без штриховки.
