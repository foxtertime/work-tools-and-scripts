# Статус «Ожидает комментарий» — дизайн

Дата: 2026-11-21. Тулзы: `cvesummary` (основная), `cvereview`.

## Зачем

После пройденного ревью разработчик должен оставить комментарий в задаче.
Это последний этап перед «Готов». Сейчас такие задачи либо остаются
«Ожидает ревью», либо становятся «Готов» раньше времени; отдельный статус
делает этот этап видимым.

## Что строим

`cvesummary`: статус «Ожидает комментарий» (регистр и лишние пробелы не
важны) — **отдельная роль**, которая во всех расчётах ведёт себя как
«Ожидает ревью», но во всех отображениях видна отдельно, пурпурным цветом.

- Расчёты как у ревью: задача открыта и «в работе» для часов и нагрузки;
  с корректной `End date` не позже даты отчёта — выполнена для скорости
  (общей, личной, сценариев, мощности прогноза); в блоке темпа — закрыта
  (остаток, баланс, графики закрытия), без повторного вычитания в сценарии
  «без задач с готовым решением».
- Отображение отдельно от ревью: сегмент «Комментарий» в полосе шапки сразу
  после «Ревью»; роль «Ожидает комментарий» в полосе и счётчиках личной
  карточки; раздел «Ожидает комментарий по принятой мере» под «На ревью по
  принятой мере»; своя часть столбика и запись легенды на таймлайнах
  разработчиков (общем и личном) с отдельной выборкой по клику; пурпурный
  цвет в статусах и списках; в «Состоянии» — «ревью N · комментарий N ·
  пауза N».
- Цвет `--st-comment`: пурпурный, отличимый от `--c7` (фиолетово-синий
  цвет разработчика) и от бирюзового ревью, в светлой и тёмной темах.

`cvereview`: «Ожидает комментарий» входит в пул ревью наравне с «Ожидает
ревью» и «Готов» и есть в фильтре статусов.

## Подходы

1. Склеить с ревью (`isReview` распознаёт оба статуса) — дёшево, но без
   отдельного цвета; отвергнут пользователем.
2. **Отдельная роль `isComment` плюс общая `isSubmitted` для расчётов** —
   выбран: расчёты меняются в одной точке, отображения получают свой ключ.

## Не делаем

- Не меняем правило «изменилось после ревью» в `cvereview`: смена статуса
  по-прежнему требует повторной проверки, как сейчас при переходе в «Готов».
- Не трогаем `vulnsheet`, `dashboard`, `taskhistory`, `patchaudit` — они не
  разбирают статус разработчика.
- Не меняем генератор демо-таблицы `tests/example.py`.

## Решения исполнителя (Claude)

- Узор комментария на таймлайнах: пурпурная точка с белой обводкой поверх
  цвета разработчика/меры (у ревью — белая точка).
- Версии: `cvesummary` 1.43.0, `cvereview` 0.9.0 (MINOR — новая
  функциональность).
