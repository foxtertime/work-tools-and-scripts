# Статус «Убрано из эпика»

Дизайн по обсуждению с пользователем 2026-11-05. Дизайн подтверждён пользователем;
реализация завершена по согласованному плану. Столбец — «Статус» разработчика,
а не Task state тасктрекера.

## Уточнение интерфейса 1.26.1

По запросу пользователя из подписей и подсказок общей полосы убрана
приписка «без убранных». В блоке «Состояние» убранные вынесены в отдельный
счётчик, остальные счётчики исключают их. Эти четыре категории не
пересекаются и по клику открывают свой состав. Это уточнение заменяет
описанное ниже включение убранных в смысловые счётчики шапки; для личных
карточек и расчётов скорости/прогноза прежние правила сохраняются.

## Смысл и расчётная роль

Новый статус сохраняется в исходных данных и списках как «Убрано из эпика».
Сравнение статуса и SecOps не учитывает регистр и крайние пробелы.
Визуальный признак убранной задачи отделён от её расчётной роли.

| Исполнитель и даты | Роль |
| --- | --- |
| SecOps, любые даты или их отсутствие | Готово |
| Другой разработчик, Start date и End date заполнены | Готово |
| Другой разработчик, Start date заполнена, End date нет | В работе |

Техническое решение для неполных/ошибочных строк: у другого разработчика
без Start задача остаётся открытой и назначенной; применяется существующая
диагностика отсутствующего старта. При пустом разработчике — открытая и
не взятая. Неразобранная дата не доказывает завершение; ошибки дат остаются
в аномалиях. Остальные ранее существовавшие правила статусов и валидации
не пересматриваются этой задачей.

Расчётная роль определяется в одном месте и применяется одинаково к
остатку, часам, скорости, прогнозу, разрезам и раскрытию списков.

## Учёт во всех разделах

Никакой общей фильтрации убранных строк нет. Они сохраняются в количестве
строк, уникальных пар CVE + компонент, компонентов, критичности, RHEL,
мерах, AI/remediation, исходных списках, поиске и CSV. Группировка AI по
парам и выбор наиболее свежего вердикта остаются прежними.

Закрытые убранные задачи входят в готовность и уменьшают открытый остаток.
Открытые убранные задачи входят в остаток, работу разработчика и прогноз.
При наличии оснований они попадают в «Можно закрыть» обычным образом.
Поступление по Task date сохраняется независимо от нового статуса.

Закрытие входит в скорость и столбик завершений только при наличии
наблюдаемой End date. Для SecOps без End date закрытое состояние известно,
а дата закрытия неизвестна: событие завершения не выдумывается. В
накопительных графиках сохраняется существующее поведение «Готов» без
End date — задача считается закрытой с поступления, чтобы остаток совпадал
со статусами снимка.

Часы считаются по существующим правилам расчётной роли. У обычного
разработчика Start/End задают интервал; при отсутствии End работа
продолжается и предотвращает личный перерыв. Для закрытого SecOps без
End часы неизвестны, как для обычного «Готов» без End у SecOps.
Исключение SecOps из будущей мощности команды и её активности сохраняется.
Пересечения перерывов и порог пять рабочих дней не меняются.

## Дубликаты

Убранные строки полностью исключаются из определения дубликатов:
не выбираются основной строкой, не делают другие строки дубликатами,
сами не получают основание «Дубликат». Остальные строки группы выбирают
основную между собой по существующим правилам. Для группы только из
убранных строк дубликатов нет. Уникальные пары продолжают учитывать все
строки; это отдельный счётчик, а не правило дубликатов.
В раскрытии уникальной пары при наличии обычных строк представитель
выбирается среди них, чтобы убранная строка не подменяла актуальную.
Если все строки пары убраны, представитель остаётся из этой пары.

## Полосы и счётчики

В общей полосе шапки и в личной полосе статусов (.pbar) первый слева сегмент —
«Убрано из эпика», графитового цвета. Он содержит все убранные строки
соответствующей выборки, независимо от расчётной роли. Каждая строка
занимает ровно один сегмент: убранная не дублируется в зелёном/синем или
сегментах оснований закрытия. Остальные сегменты сохраняют порядок.

В шапке существующее правило триажа применяется и к графитовому сегменту:
есть разработчик либо Исполнитель = УА. Новое название статуса само по
себе не подменяет правило триажа. Триаж не добавляется в остальные полосы,
где его сейчас нет. Столбики по датам и полосы мер сохраняют свои цвета.
На графитовом фоне штриховка и текст
должны различаться в обеих темах. Оттенки выбирает реализатор.

Смысловые счётчики «Готово» и «В работе» включают убранные задачи по роли
и поясняют включённое подмножество: «Готово: 8, из них убрано из эпика: 2».
Если убранные есть среди работающих, у работающих аналогичное пояснение.
Всё количество задач остаётся прежним: подмножества не прибавляются к нему.

Согласованный пример: шесть обычных готовых, две убранные готовые и две
обычные в работе. Полоса — 2 графитовых + 6 зелёных + 2 синих; счётчик
готовых — 8, в том числе 2 убранных; в работе — 2; всего — 10.

Техническое решение для подписей непосредственно сегментов и их скобок:
число всегда соответствует только строкам сегмента. У обычных сегментов
явно указывается «без убранных», когда иначе возникнет неоднозначность.
Это визуальные подмножества; смысловые общие счётчики сохраняют полные
значения и пояснения «из них». В графитовом сегменте подсказка дополнительно
показывает, сколько задач расчётно закрыто и сколько ещё открыто.

## Раскрытие списков

Графитовый сегмент открывает все убранные строки своей полосы. «Готово: 8»
открывает восемь расчётно готовых; «из них убрано: 2» — соответствующие две.
Зелёный сегмент открывает только свои шесть. Аналогично для работающих и
для общей полосы. Количество, подпись и состав списка совпадают.
Обновляются также легенды, скобки и ARIA-подписи; старая привязка по
индексам не должна смещать выборки при добавлении первого сегмента.

## Подход

Единые предикаты расчётной роли в roles.js плюс отдельный предикат
isRemoved. hours/pace/activity и представления используют одни и те же
роли. Визуальные разбиения полос остаются непересекающимися; смысловые
счётчики и их пояснения рассчитываются отдельно. Это технический выбор
реализатора, основанный на согласованном разделении роли и цвета.

## Проверки и поставка

Проверить таблицу ролей, SecOps без дат, обычного разработчика с обеими
датами и только со Start, неполные строки, группы дубликатов со смешанными
статусами и только из убранных. Проверить часы, закрытия, остаток, прогноз,
поступления и сохранность AI-группировки. В браузере — порядок сегментов,
триаж графита, смысловые счётчики и точные выборки, светлую/тёмную темы,
узкое окно, вариант только с убранными задачами и отсутствие нового статуса.
