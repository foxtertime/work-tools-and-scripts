# cvesummary: сводка по CVE из таблицы процесса

**Дата:** 2026-10-19

## Задача

Таблицу процесса устранения CVE ведут в Excel: строки делает `vulnsheet`,
колонки процесса (`Разработчик`, `Статус`, даты, `Принятая мера`)
заполняют люди. Чтобы показать, где работа встала, на ком сколько висит,
успеваем ли к релизу и что показать наверх, нужна сводка — одна HTML-страница
с плитками, разрезами, прогнозом и карточками разработчиков.

`cvesummary` превращает xlsx этой таблицы в такую страницу. Образец вида и
состава блоков — `Сводка по CVE.html` (собрана вручную на вымышленных
данных); тулза воспроизводит её с поправками, перечисленными ниже. Значения
`Статус` и `Принятая мера` — из `task.md` в корне рабочей копии.

## Вне рамок

- ~~Вход CSV: только xlsx.~~ С версии 1.1.0 CSV принимается (по расширению
  `.csv`); как он читается — в `README.md`, «Что читается из CSV».
- Раздел CVE в `dashboard` (`task.md`) — отдельная задача, эта тулза её не
  делает и с `dashboard` кода не делит.
- `Task state` в расчётах и на графиках не участвует.
- Праздники и история статусов: в таблице их нет.
- Полная таблица строк на странице: в образце её нет.

## Запуск

```sh
python3 -m cvesummary ТАБЛИЦА.xlsx [-o СВОДКА.html] [--as-of ГГГГ-ММ-ДД]
python3 -m cvesummary --version
```

- Python 3.9+, только стандартная библиотека; конфига нет.
- Без `-o` страница пишется рядом с таблицей: `<имя таблицы>.html`.
  Существующий файл перезаписывается с предупреждением в журнал.
- `--as-of` — дата отчёта, по умолчанию сегодня. От неё считаются часы
  открытых задач, окно темпа и прогноз.
- Коды возврата: `0` — страница записана; `2` — вход не читается, нет шапки
  или обязательных колонок, неверная дата в `--as-of`.

## Чтение xlsx

Своим разбором, через `zipfile` и `xml.etree.ElementTree`: `openpyxl` в
RHEL 9 нет.

- **Лист** — первый в `xl/workbook.xml` (порядок `<sheets>`), путь — через
  `xl/_rels/workbook.xml.rels`. Остальные листы не читаются.
- **Ячейки.** Адрес `r="C5"` задаёт колонку; пропущенные ячейки посреди
  строки — пустые. Типы: `s` (shared strings, rich text склеивается из
  `<r><t>`), `inlineStr`, `str` (результат формулы), `b` (`TRUE`/`FALSE`),
  `e` (текст ошибки, например `#N/A`), число без `t`. Целое число пишется
  без `.0`.
- **Даты.** Число со стилем даты переводится в дату: встроенные `numFmtId`
  14–22 и 45–47 и собственные `numFmts`, в коде формата которых вне кавычек
  и `[…]` есть `d`, `m` или `y`. Учитывается `date1904` из
  `<workbookPr>`. В колонках дат (`Task date`, `Start date`, `End date`,
  `Fix date`) текст `дд.мм.гггг`, `гггг-мм-дд` и серийное число тоже
  разбираются; в тексте допустимо время после даты (`дд.мм.гггг чч:мм`).
  Время в дате отбрасывается. Правдоподобны даты с 01.01.2000 по
  31.12.2099 включительно: остальные (опечатка `01.10.0206`, число `5`
  вместо даты) считаются нераспознанными. Нераспознанная дата остаётся
  текстом и попадает в аномалии.
- **Шапка** — первая строка листа, в которой есть ячейка `CVE ID`. Строки
  выше (например, группировка `AG21` / `SberLinux` / `RedHat`)
  пропускаются.
- **Колонки** ищутся по имени без учёта регистра и крайних пробелов;
  пробелы и переносы строк внутри имени схлопываются в один пробел
  (`SL NVR⏎(latest build)` — та же колонка). Лишние игнорируются, порядок любой. Повтор имени — берётся первая,
  предупреждение в журнал.
  - Обязательные: `CVE ID`, `Компонент`, `RHEL state`, `RHEL severity`.
    Нет хотя бы одной — код 2 со списком недостающих.
  - Остальные колонки `vulnsheet` 2.0 (`Разработчик`, `Статус`,
    `Start date`, `End date`, `Принятая мера`, `Task ID`, `Task date`,
    `Исполнитель`, `P`, `D`, `SL NVR (latest build)`, `RHEL NVR (if fixed)`,
    `Fix date`, `RHEL CVSS`, `Advisory (RHSA)`, `CVE link`, `Комментарий`)
    необязательны: отсутствующая читается пустой, журнал её называет.
    `Task state` не читается.
- **Значения.** `-`, `—` и пустая ячейка — «нет значения». Полностью пустая
  строка пропускается молча; строка без `CVE ID` пропускается и считается.
- **Ошибки входа** — не zip, нет `workbook.xml` или листа, битый XML,
  шапка не найдена — сообщение с именем файла и код 2.

Python больше ничего не считает: он отдаёт странице нормализованные строки.

## Данные в странице

Страница — один HTML-файл: CSS и JS тулзы встроены, шрифты подключаются с
Google Fonts, как в образце (без сети остаются запасные шрифты). Данные —
в `<script type="application/json" id="data">`. В JSON экранируются `<`,
`>` и `&` (`\u003c`, `\u003e`, `\u0026`), чтобы ни `</script>`, ни `<!--` не закрыли блок.

```json
{
  "meta": {"version": "1.0.0", "source": "table.xlsx", "sheet": "Лист1",
           "header_row": 2, "as_of": "2026-10-19", "skipped": 3,
           "missing": ["Комментарий"], "bad_dates": 1},
  "rows": [{"row": 3, "dev": "Иванов И.И.", "status": "Готов",
            "start": "2026-10-01", "end": "2026-10-03", "measure": "…",
            "task": "…", "cve": "CVE-2026-1234", "tdate": "2026-09-28",
            "exec": "…", "comp": "openssl", "p": "+", "d": "",
            "slnvr": "…", "rhnvr": "", "fixdate": "", "rstate": "Affected",
            "sev": "Important", "cvss": "7.5", "rhsa": "", "link": "…",
            "comment": "", "bad": ["end"]}]
}
```

`row` — номер строки в листе, для ссылок из аномалий. `bad` — колонки дат,
которые не разобрались (их значение оставлено текстом).

## Роли статусов

Только по `Статус` разработчика, без учёта регистра и крайних пробелов.
Значения — из `task.md`.

| Роль | Правило |
|---|---|
| не взята | `Разработчик` пуст, статус не «Готов» |
| готово (закрыта) | `Статус` = «Готов», с разработчиком или без |
| на ревью | «Ожидает ревью» |
| на паузе | «На паузе» |
| требует внимания | «Есть проблема», «Нужна доработка» |
| в работе | разработчик есть, статус не «Готов» (включая ревью, паузу, внимание, пустой и неизвестный) |

Открытая задача — всё, что не «Готов». «Ожидает ревью» — открытая и для
часов не отличается от «В работе». Статус вне набора показывается как есть.

## Меры

Порядок на графиках — как в `task.md`: «Патч из апстрима», «Импорт новой
версии», «Тег свежего билда», «Пакет пересобран (если в зависимостях)»,
«Обоснована неприменимость», «Патч из прошлой ветки», «Самописный патч»,
«Было исправлено ранее», «Закрыто SecOps», «Написана мера компенсации»,
«Другое». Значение вне списка показывается как есть после них; пустое —
«не указана». Сравнение — без учёта регистра и крайних пробелов, подпись —
из списка.

## Критичность

`RHEL severity` в порядке Critical → Important → Moderate → Low, затем
незнакомые значения как есть, затем «Нет оценки» (пусто). Цвета — тёплая
шкала образца.

Разработчики, компоненты, `RHEL state` — как в данных; цвета разработчиков —
палитра из 8 по убыванию числа задач, остальные серые.

## Часы

Скорость меряется в часах работы, а не в календарных днях.

**Интервал задачи.** Задача попадает в расчёт, если у неё есть
`Разработчик` и `Start date`. Интервал — от `Start date` до `End date`
включительно; без `End date` — до даты отчёта. Конец позже даты отчёта
обрезается по ней. В расчёт не попадают (и уходят в аномалии):

- `End date` раньше `Start date`;
- «Готов» без `End date` — иначе закрытая задача ела бы часы до сегодня;
- нераспознанная `Start date` или `End date`;
- разработчик есть, `Start date` нет.

`Start date` позже даты отчёта — интервала нет, часов 0, не аномалия.

**Рабочий день.** Для разработчика X день D рабочий, если это будний день
(пн–пт) или если у X есть задача, у которой `Start date` = D или
`End date` = D: взял или закрыл задачу в выходной — значит, работал.

**Доля.** В рабочий день D у X висят N(D) задач — те, чьи интервалы
покрывают D. Каждая получает 8 / N(D) часов. В нерабочий день часов нет.

**Трудоёмкость.** Часы задачи — сумма её долей по интервалу. У закрытой —
итог, у открытой — «вложено пока».

Пример: X берёт A в пн и закрывает в ср, B берёт во вт и закрывает в
следующий пн, C закрывает в субботу, взяв в пятницу.

| День | Висят | A | B | C |
|---|---|---|---|---|
| пн | A | 8 | | |
| вт | A, B | 4 | 4 | |
| ср | A, B | 4 | 4 | |
| чт | B | | 8 | |
| пт | B, C | | 4 | 4 |
| сб (закрыта C) | B, C | | 4 | 4 |
| вс | B | | — | |
| пн | B | | 8 | |
| **итого** | | **16** | **32** | **8** |

Время закрытия внутри дня неизвестно, поэтому день закрытия делится наравне
с остальными: X берёт первую задачу в пн (8 ч), во вторник ещё три (8 / 4 =
2 ч каждой), в среду сдаёт первую — висят те же четыре, ей ещё 2 ч. Итого
первая задача — 12 ч.

**Где используются часы.** Трудоёмкость закрытых задач даёт среднее и
медиану часов на задачу — в целом, по разработчику, по критичности, по
мере; скорость разработчика — сколько задач он закрывает за 8-часовой
рабочий день. Прогноз «успеем ли» часов не использует: он в задачах.

## Блоки страницы

Как в образце, с заменами:

- **Шапка.** Всего задач, уникальных CVE, компонентов; период по
  `Task date`; дата отчёта; источник (файл, лист).
- **Состояние.** Готово; в работе (из них на ревью, на паузе); не взято.
  Плитки «Отменено» нет.
- **Можно закрыть.** Открытые, у которых `RHEL state` = Fixed, или `P` =
  `+`, или `D` = `+`; по каждому основанию отдельно и без повторов.
  С версии 1.2.0 четвёртое основание — дубликат (та же пара CVE + компонент);
  правило выбора основной строки — в `README.md`, «Можно закрыть».
  Структурная полоса — как в образце, без «Отменено».
- **Риски и темп.** Открытые Critical и Important; требует внимания;
  «часов на задачу» — среднее и медиана по закрытым с часами (вместо «дней
  в среднем до готовности»).
- **Разрезы по критичности и мерам** — как в образце; колонка «Ср. срок»
  заменена на «Ср. часов».
- **Темп и прогноз** — в задачах, как в образце; часов в прогнозе нет.
  - Поступление (по `Task date`) и закрытие («Готов» по `End date`) по
    дням за весь период и среднее за 7.
  - Окно темпа 7 / 14 / 30 дней, сканфриз и целевая дата — поля на
    странице, запоминаются в `localStorage`.
  - Темп за окно: поступает задач в календарный день, закрывается в
    день, баланс; открыто на дату отчёта.
  - Прогноз — по дням от даты отчёта: остаток открытых задач плюс
    поступление до сканфриза (без сканфриза — бессрочно) минус закрытие
    в текущем темпе; дата, когда остаток дойдёт до нуля, или «не
    завершится».
  - Строки прогноза — как в образце: со сканфризом или без; если новые
    перестанут поступать сегодня; без задач с готовым решением.
  - Целевая дата — сколько задач в день нужно закрывать, против
    текущего темпа.
- **Требует внимания** и **Можно закрыть** — таблицы образца плюс колонка
  «часов» (вложено пока).
- **Компоненты, RHEL state, статусы разработчиков, поступление по неделям**
  — как в образце, без графика по `Task state`.
- **Разработчики.** Карточка: назначено и разбивка по ролям; сделано по
  критичности и по мерам; скорость — среднее и медиана часов на задачу,
  закрыто за рабочий день за окно и с первого старта; загрузка на дату
  отчёта — «висит N, по 8/N ч»; закрытия по дням с первого
  старта разработчика.
- **Сжигание по неделям** — как в образце.
- **Аномалии** — новый блок: строки, не попавшие в часы, с причиной и
  номером строки листа; сколько строк без `CVE ID` пропущено; колонки,
  которых нет в таблице.
- **Пояснения** внизу — правила ролей, часов и «можно закрыть» словами.

### Графики по времени

Дневные и недельные графики — темп по дням, поступление и сжигание по
неделям, закрытия в карточке разработчика — показывают весь период, без
обрезки: от первой даты в данных (`Task date`, `Start date`, `End date`) до
даты отчёта. У столбика дня или недели есть минимальная ширина (дневной — 10
px, недельный — 28 px). Если весь период в ширину карточки не помещается,
график прокручивается по горизонтали внутри своей карточки:

- полосы прокрутки не видно (`scrollbar-width: none`, `::-webkit-scrollbar`);
- при открытии график стоит в конце — на последних днях;
- листается перетаскиванием мышью, Shift+колесом, тачпадом и пальцем;
  вертикальное колесо без Shift прокручивает страницу, как обычно;
- у края, за которым есть ещё дни, — затухающий градиент; у края, где
  данных больше нет, его нет;
- ось значений не уезжает вместе со столбиками;
- страница целиком горизонтально не прокручивается, в том числе на ширине
  телефона.

## Журнал прогона

В stderr: лист и номер строки шапки; найденные и отсутствующие
необязательные колонки; строк данных, пропущено без `CVE ID`, дат не
разобрано; дата отчёта; куда записано (и что файл перезаписан).

## Раскладка

```text
tools/cvesummary/
├── README.md  TODO.md  CHANGELOG.md
├── cvesummary/
│   ├── __init__.py   __main__.py   cli.py
│   ├── xlsx.py       # zip → лист → строки ячеек, типы, даты по стилю
│   ├── table.py      # шапка, колонки по именам, нормализация, ошибки
│   ├── page.py       # HTML из assets + JSON данных
│   └── assets/       # summary.html, summary.css, js/*.js
├── tests/            # unittest
└── tests/js/         # node --test
```

JS разбит на чистые модули — роли, часы, прогноз, ширина графиков — и
отрисовку с прокруткой. Чистые
модули тестируются в node без DOM; `page.py` склеивает их в один
`<script>`.

## Тесты

- **Python (`unittest`).** xlsx собираются в тестах через `zipfile`:
  shared и inline strings, rich text, дата числом со стилем 14 и с
  собственным форматом `dd.mm.yyyy`, `date1904`, пропуски ячеек посреди
  строки, группировка над шапкой, лишние колонки и другой порядок, повтор
  имени колонки, строка без `CVE ID`. Ошибки: не zip, нет листа, нет шапки,
  нет обязательных колонок. Страница: данные лежат в JSON-блоке, `</script>`
  в ячейке его не ломает. CLI: `-o` по умолчанию, перезапись, `--as-of`,
  коды возврата.
- **JS (`node --test`).** Часы: одна задача; две параллельно по 4 ч;
  выходной без старта и закрытия, со стартом, с закрытием; старт и закрытие в один день;
  открытая до даты отчёта; обрезка по дате отчёта; пример из раздела
  «Часы» целиком. Роли: регистр и пробелы, неизвестный статус, ревью —
  открытая. Прогноз: нулевой темп закрытия, поступление больше закрытия,
  сканфриз, целевая дата в прошлом.
- **Руками.** Пример на 100 строк переделывается под статусы и меры из
  `task.md`, по нему собирается страница и открывается в браузере: консоль
  без ошибок, блоки заполнены, тёмная тема читается, ширина телефона без
  горизонтальной прокрутки.
