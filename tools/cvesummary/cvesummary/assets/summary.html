Компоненты

Сколько CVE приходится на пакет, с разбивкой по критичности. Все пакеты, по убыванию; список листается.

Состояние в RHEL

поле RHEL state

Статус задач

статус у разработчика

Поступление задач

По полю Task date, неделя начинается в понедельник, с разбивкой по критичности (RHEL severity)

Разработчики

Сжигание: задачи со статусом «Готов» по End date, с разбивкой по разработчикам

Аномалии

Строки, которые не попали в расчёт часов, и даты, которые не разобрались. Строка — номер строки листа.

    СтрокаCVEКомпонентРазработчикСтатусStart dateEnd dateПричина
    Готово:
    статус разработчика «Готов».
    В работе:
    разработчик назначен, статус не «Готов». На ревью — «Ожидает ревью», на паузе — «На паузе»; обе открытые.
    Не взято:
    разработчик не назначен.
    Требует внимания:
    «Есть проблема» или «Нужна доработка».
    Часы:
    в рабочий день разработчика его 8 часов делятся поровну между задачами, которые на нём висят — от Start date до End date включительно, у открытых до даты отчёта. Выходной рабочий, если в этот день он взял или закрыл задачу. Часы задачи — сумма её долей.
    Можно закрыть:
    открытая задача, у которой RHEL state = Fixed, или P = + (патч уже у нас), или D = + (наша версия вне уязвимого диапазона), или это дубликат — открытая строка с той же парой CVE ID + Компонент, что у основной.
