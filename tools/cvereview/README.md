# cvereview

Автономная HTML-страница для ревью CSV `vulnsheet`: компактные карточки,
чеклисты по принятой мере, пулы проверенных/проблемных и переносимый JSON.

**Версия: 0.2.1** — источник в `VERSION`, видна внизу страницы.
История — [CHANGELOG.md](CHANGELOG.md).

## Запуск

Откройте [cvereview.html](cvereview.html) в настольном Chrome двойным кликом.
Для работы не нужны сервер, Python, npm и доступ к API. CSS, JavaScript,
шрифты и иконки встроены; данные не отправляются в сеть. Интернет нужен
только при переходе по ссылкам в тикет, GitLab, CVE или RHSA.

1. **Загрузить CSV** — выбрать файл vulnsheet или перетащить на страницу.
2. При продолжении работы — **Загрузить состояние JSON**.
3. Проверять пункты справа: пусто — не смотрелось, ✓ — ок, ✕ — не ок.
4. Кнопка **«Проверено»** доступна, когда все пункты отмечены ✓ или ✕. При крестиках
   можно завершить ревью либо выбрать **Есть проблема** с обязательным
   комментарием. Число замечаний подсвечено.
5. **Сохранить состояние JSON** скачивает `<имя CSV>.review.json`.
   Завершите скачивание, чтобы перенести или надёжно сохранить результаты.

[Пример CSV](examples/vulnsheet-demo.csv) содержит вымышленные строки для
всех 11 мер; это не сведения о реальных CVE, сборках и advisory.

## Пул и интерфейс

В пул входят **«Ожидает ревью» и «Готов»**, разработчик указан и не `SecOps`.
Регистр и лишние пробелы статусов/SecOps не важны. `Task state` не определяет
пул. «Готов» разработчика не означает «Проверено»: обе группы требуют проверки.

Около 3/4 карточки — контекст, сборки, P/D, комментарии, ссылки и раскрытие
всех исходных полей. Справа чеклист и решения. На узком экране чеклист снизу.
Поиск, фильтры, сортировка и страницы по 50 карточек не сбрасывают отметки.
В «Проблемах» можно менять комментарий и возвращать задачу на ревью.
В пуле «Проверено» чеклист доступен для чтения, есть возврат. Последний перенос
или изменение замечания можно отменить; загрузка файлов сбрасывает отмену.

P `+` — патч найден в PATCH коммита сборки, D `+` — версия вне известных
уязвимых диапазонов. Минус не доказывает уязвимость: проверка могла не
выполниться или не получить подтверждения. Эти поля не проставляют галочки.

## Чеклисты по мере

Все 11 пользовательских наборов и окончательные короткие формулировки —
в [полном списке проверок](docs/checklists.md). В наборах от 2 до 9 пунктов;
число проверок и доступность «Проверено» вычисляются по выбранному набору.

Источник — [assets/checklists.json](assets/checklists.json). У профиля есть
постоянный `id`, `version`, подпись `label`, значения CSV `measures` и
пункты `items` с собственными `id`, `label`, `description`. Старые названия
мер из vulnsheet поддерживаются как варианты в `measures`.

- Переформулировка `label`/подсказки и перестановка пунктов сохраняют отметки:
  соответствие определяется по ID, а не по подписи или позиции.
- Новый пункт получает новый ID, начинается пустым и возвращает задачу
  в «На ревью». Совпадающие по ID отметки сохраняются.
- Удалённый пункт остаётся в предыдущем ревью. Если остальные пункты уже
  проверены, удаление не снимает завершение ревью.
- При изменении смысла проверки нужен новый ID; удалённые ID не используют
  для других смыслов. Явное увеличение `version` без изменения состава
  пунктов означает обязательную полную повторную проверку профиля.
- При смене самой принятой меры или исходных данных отметки сбрасываются;
  прежнее решение сохраняется для сравнения.

Измените JSON и выполните `python3 build.py`: справочник и список проверок
встроятся в один HTML. Для загрузки пользовательских CSV сборка не нужна.
Чтение `checklists.json` из сети/соседней папки при работе не используется.
Пустая или неизвестная мера получает явно обозначенный общий набор из
«Комментарий добавлен» и «Задача закрыта корректно». Проверки ручные;
API Koji/GitLab тулза не вызывает.

## CSV

Поддерживаются UTF-8 с BOM/без и Windows-1251, разделители `;`, `,`, табуляция,
кавычки и многострочные поля. Шапка находится по `CVE ID`, строки выше
пропускаются. Порядок колонок произвольный. Обязательны `Task ID`, `CVE ID`,
`Компонент`, `Разработчик`, `Статус`; остальные и лишние колонки доступны
в подробностях. Диагностика показывает отсутствующие необязательные поля.

Без полного идентификатора Task ID/CVE/компонент карточка не создаётся;
номера пропущенных записей видны в диагностике. Точные дубликаты объединяются,
конфликтующие отклоняют файл целиком. XLSX, UTF-16 и повреждённый CSV не
поддерживаются. Ошибочный CSV не заменяет открытую работу.

## Состояние и обновления

JSON содержит `app: cvereview`, `schemaVersion: 1`, настройки, идентичности
задач, профили/версии/снимки чеклистов, отметки, пулы, комментарии, даты
и существенный контекст исходных строк. Прототипное хранилище сюда не переносится.

Сопоставление — по Task ID + CVE + компонент, без привязки к порядку строк
и имени CSV. Изменились мера, сборка, существенные поля —
задача возвращается в «На ревью» с пустыми отметками и подписью
**«Изменилось после ревью»**. Прежнее решение и изменённые поля доступны
в истории. Перестановка строк и изменение Task state не сбрасывают решения.

Выбранный JSON явно переопределяет содержащиеся в нём решения; остальные
сохраняются. Более поздняя дата не выигрывает автоматически. Несопоставленные
решения остаются архивными и входят в следующий экспорт. Неверная схема,
дубликат идентичности или неверные состояния отклоняют весь импорт без
частичного применения. Настройки из валидного JSON тоже применяются.

Автосохранение в браузере хранит последнюю таблицу и состояние, восстанавливает
их после перезагрузки. Это кеш конкретного браузера/профиля: перенос HTML
или очистка хранилища его не переносит. Для file:// не следует рассчитывать
на общий кеш разных путей HTML. При отказе/переполнении хранилища видно
сообщение, JSON по-прежнему можно скачать. Исходный CSV не изменяется.

Индикаторы различают кеш в браузере и изменения после выгрузки JSON.
Страница не перезаписывает JSON на диске автоматически: кнопка подготавливает
скачивание, которое нужно завершить в браузере.

## Ссылки

В **Настройках** задайте реальный шаблон GitLab, например
`https://gitlab.example.internal/rpms/{component}` с вашим хостом/namespace.
До настройки кнопка недоступна. Координат репозитория в CSV нет.
Подстановки `{task}`, `{component}`, `{cve}` кодируются как части URL.

Шаблон адреса тасктрекера задаётся там же, например
`https://tracker.example.internal/task/{task}`. По умолчанию он пустой;
до настройки кнопка тикета недоступна. Поле можно очистить и сохранить.
Если в Task ID уже записан HTTP(S)-URL, он используется напрямую. CVE — из `CVE link` или Red Hat,
RHSA — только при валидной ссылке в `Advisory (RHSA)`. Новые вкладки,
без API и токенов. Настройки также содержат необязательное название релиза.

## Разработка

Сборка требует только Python 3.9+, без сторонних зависимостей:

```sh
python3 build.py
python3 build.py --check
```

Исходники в `assets/`, готовый `cvereview.html` хранится в репозитории.
Сборка приложения выполняется без сети; таблицы пользователя не требуют сборки.

Модульные тесты (Node.js 18+):

```sh
node --test tests/*.test.cjs
```

Браузерный тест требует установленного Playwright и Chromium:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright node tests/browser.cjs
```

Если `playwright` доступен напрямую, переменную можно не задавать.
`CHROME_BIN=/absolute/path/to/chrome` выбирает браузер; `TMPDIR` — доступный
временный каталог. Проверяется настоящий HTML через file://, загрузка CSV/JSON,
скачивание, чеклисты, кеш, атомарность, история, пагинация, мобильная раскладка
и отсутствие внешних запросов. Внутренние API не нужны.

Шрифты Onest, Unbounded, JetBrains Mono — Google Fonts, SIL Open Font License.
Файлы/лицензии в `assets/fonts/`, лицензии также включены в HTML. Разбор CSV
адаптирует правила cvesummary без зависимости от соседней тулзы.
[Прототипы](prototypes/index.html) сохранены как история выбора;
для работы используйте `cvereview.html`.
