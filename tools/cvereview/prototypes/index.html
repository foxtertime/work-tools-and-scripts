CVEREVIEW / UI EXPLORATION

Как будем ревьювить CVE?

Пять интерактивных примеров для ревью задач разработчиков. Откройте вариант и попробуйте рабочий процесс. Загрузка таблицы появится после выбора интерфейса.

05 ВАРИАНТОВ · OFFLINE HTML
ВАРИАНТ 01

Карточки↗

Контекст + чеклист · в духе cvesummary

Слева контекст задачи, справа чеклист с отметками ✓ / ✕ / пусто. «Ревьювед» активна после проверки всех пунктов.

Подходит для: Последовательное ревью с явной проверкой каждого пункта
ВАРИАНТ 02

Входящие↗

Очередь + подробности

Список слева, полная карточка справа. Больше места для сборок, комментариев и исходных полей.

Подходит для: Долгое ревью с частым переключением между задачами
ВАРИАНТ 03

Доска↗

Три пула одновременно

На ревью, проблемы и проверенные задачи видны рядом. Каждая карточка меняет колонку после решения.

Подходит для: Контроль движения задач и возвратов на доработку
ВАРИАНТ 04

Фокус↗

Одна задача за раз

Тёмное рабочее место с крупной карточкой, очередью и прогрессом. После решения открывается следующая задача.

Подходит для: Последовательное ревью без постоянного выбора следующей задачи
ВАРИАНТ 05

По разработчикам↗

Дизайн cvesummary

Тёмная шапка, шрифты и палитра cvesummary. Задачи сгруппированы по разработчику, ссылки и решения доступны сразу.

Подходит для: Проверка всех решений одного разработчика подряд
КАК СРАВНИВАТЬ

Один процесс.
Пять способов работать.

Во всех вариантах одинаковые вымышленные строки vulnsheet и одинаковые действия: «Ревьювед» убирает задачу из очереди, «Есть проблема» требует комментарий и отправляет её в отдельный пул.

Попробуйте проверить пару задач, оставить замечание и открыть проблемный пул. Решения сохраняются отдельно для каждого варианта.

Для начала я бы сравнил 01 «Карточки» и 02 «Входящие»: первый ближе к cvesummary, второй даёт больше места для детального ревью.
