# Фильтры: три положения, группы и меню

**Дата:** 2026-08-06

## Задача

Фильтр сейчас умеет ровно одно: «оставь строки, у которых это есть».
Набор — плоский список ключей, все складываются по И, а поставить их можно
только кликом по плашке. Вопрос «где есть CVE-патч и при этом нет
autogen-патча» страницей не задаётся никак.

Строка чипов под панелью управления показывает поставленное и снимает по
клику. Она отвечает на вопрос «почему строк так мало», но других ответов
дать не может: чипом нельзя ни поставить фильтр, ни увидеть тот, который
ещё не поставлен.

Фильтры переезжают в меню под кнопкой, у каждого признака появляется третье
положение, а у группы признаков — выбор между И и ИЛИ. Плашки продолжают
работать как раньше.

## Что не меняется

- **Плашки остаются органом управления.** Клик по плашке ставит и снимает
  фильтр, как сейчас.
- **Ключи фильтров.** `cve`, `has-patch`, `patches+` и прочие остаются
  теми же строками — в ссылке, в метках строк и в плашках.
- **Старые ссылки.** `#tab=state&f=cve,autogen` открывает ровно тот же
  срез, что и раньше.
- **Отсев мёртвых фильтров.** Правило «фильтр, которого нет ни на одной
  плашке, молча выбрасывается» остаётся, вместе с обеими вкладками сразу.
- **Формат снапшота, золотая фикстура, сборка в один файл.**

## Три положения

Набор фильтров вкладки перестаёт быть списком ключей и становится картой
`ключ → 1 | -1`. Единица — «есть», минус единица — «нет», отсутствие ключа
— «неважно».

```js
st.filters.state = { cve: 1, autogen: -1 };
// есть CVE-патч И нет autogen-патча
```

Проверка признака на строке — одна функция на вкладку, и она уже есть в
`stateMatches`/`diffMatches`, только вынута наружу:

| вкладка | ключ | что значит «есть» |
|---|---|---|
| Состояние | `has-patch` | `row.patches.length` |
| Состояние | `problem` | `row.problems.length` |
| Состояние | остальные | ключ стоит в `row.marks` |
| Изменения | `changed` | `row.changed` |
| Изменения | остальные | ключ стоит в `row.marks` |

`есть` требует признак, `нет` требует его отсутствия. Правило одно на все
признаки: и на метки строки, и на классы патчей, и на вычисляемые.

## Группы

Признаки разложены по группам. Группа — это и заголовок в меню, и область
действия переключателя «все / любой из».

| вкладка | id | заголовок | ключи |
|---|---|---|---|
| Состояние | `classes` | классы патчей | слаги классов, по данным снапшота |
| Состояние | `build` | свойства сборки | `has-patch`, `inherited`, `from-commit` |
| Состояние | `trouble` | проблемы | `problem`, `no-patch`, `no-source`, `gitlab-error`, `internal-error` |
| Изменения | `status` | статус | `added`, `removed`, `upgraded`, `downgraded`, `unchanged` |
| Изменения | `change` | что изменилось | `changed`, `patches+`, `patches-`, `repackaged`, `branch-changed`, `tag-changed` |

Id групп попадают в ссылку и потому неизменны. Группа без единого ключа
(классы патчей, пока не загружен снапшот с патчами) в меню не рисуется.

Порядок ключей внутри группы — тот, что в таблице выше; классы идут в
порядке `labels.classOrder`, то есть в том же, что и плашки классов.

**Как складывается.** Для каждой группы:

1. Строка отбрасывается, если у неё есть хоть один признак, помеченный
   «нет». Это правило не зависит от режима группы: «нет autogen» значит
   «точно не autogen», и складывать такое по ИЛИ — терять смысл.
2. Пометки «есть» складываются по И в режиме `все` и по ИЛИ в режиме
   `любой из`. Пустой список «есть» ничего не требует.

Группы между собой всегда по И.

**Ключ, не попавший ни в одну группу**, проверяется по И, как раньше.
Такого сейчас не бывает — таблица выше покрывает все метки, которые
выставляет `viewmodel`, — но набор меток задаётся данными, и молча терять
неизвестный фильтр нельзя: он приехал бы из ссылки и не действовал, ничем
себя не выдав.

**Умолчание режима — `все` у всех групп.** Это ровно сегодняшнее
поведение, и старые ссылки открываются без изменений. Отдельный случай,
который стоит назвать: статусы взаимоисключающие, и «появился» + «исчез» в
режиме `все` дают пустую таблицу. Так и сейчас; теперь это лечится одним
кликом по переключателю группы, а число рядом с каждой строкой меню
показывает, сколько строк подходит под неё саму.

## Правило «версия та же гасит что-то изменилось» уходит

Сейчас `toggleFilter('unchanged')` молча снимает `changed`. Костыль под
клик по плашке: пересечение читалось как «версия не менялась, но что-то
поехало» — не то, что обещает плашка.

Теперь оба признака видны в меню и ставятся осознанно, а их пересечение —
законный и полезный запрос: компоненты, у которых версия та же, а состав
патчей или RPM изменился. Правило убирается, модель становится одинаковой
для всех пар признаков.

Это единственное изменение поведения, которого не было в постановке;
человек его одобрил.

## Кнопка и меню

Кнопка **Фильтры** встаёт в панели управления перед «Expand all». Пока
фильтров нет — обычная кнопка; поставили — горит акцентом и несёт число
поставленных условий: «Фильтры · 2». Число считает и «есть», и «нет»:
условие есть условие.

Меню — плашка под кнопкой, `position: absolute` внутри обёртки
`.filterbox`, которая едет вместе с панелью управления между вкладками.

```
┌─ Фильтры · 2 ─────────────────────────┐
│ ФИЛЬТРЫ                   сбросить всё│
│───────────────────────────────────────│
│ КЛАССЫ ПАТЧЕЙ         [все][любой из] │
│   cve       1  │неважно│▓есть▓│ нет  │ │
│   autogen    0  │неважно│ есть │▓нет▓│ │
│ СВОЙСТВА СБОРКИ       [все][любой из] │
│   с патчами  3  │▓неважно▓│есть│ нет │ │
└───────────────────────────────────────┘
```

Строка меню: подпись, число, три кнопки. Число — сколько строк вкладки
подходит под этот признак само по себе, без учёта других фильтров: так же
считают плашки. Считается при открытии меню, а не на каждую перерисовку
страницы — иначе лишний проход по тысяче строк на каждый клик.

Закрывается меню кликом мимо, `Escape` и повторным нажатием на кнопку.
Кнопка несёт `aria-expanded`, плашка — `hidden`, когда закрыта. Внутри
плашки всё проходится табом; каждая тройка — `role="group"` с
`aria-label` по подписи признака, каждая кнопка — `aria-pressed`.

## Плашки

Клик по плашке переключает «есть» ↔ «неважно». Из «нет» клик тоже
снимает в «неважно»: получить с плашки обратный срез нельзя, а уйти из
него — можно.

Плашка показывает все три положения: `aria-pressed="true"` для «есть»,
класс `is-no` для «нет», ничего для «неважно». Плашка `все` нажата, когда
на вкладке не стоит ни одного фильтра.

## Ссылка

- `f=cve,-autogen` — минус перед ключом значит «нет». Ключи в `f=`
  отсортированы, чтобы одна и та же выборка давала одну и ту же строку.
- `any=classes,status` — список групп, переключённых в «любой из».
  Отсутствует, когда все группы в режиме `все`.

`hash.js` остаётся не знающим ничего о смысле: `f=` он по-прежнему режет
по запятой и отдаёт строками, минус разбирает `page.restore`. Новый ключ
`any=` разбирается там же, где и `f=`, — списком строк.

Старая ссылка минусов и `any=` не содержит: все признаки «есть», все
группы `все` — то же, что и раньше.

## Что уходит

| откуда | что |
|---|---|
| `dashboard.html` | `<div class="chips" id="chips">`; вместо него `.filterbox` с кнопкой и плашкой внутри `.controls` |
| `cards.js` | `chips()` целиком |
| `layout.css` | правила `.chips`, `.chips:empty`, `.chip`, `.chip.clear` |
| `ui.js` | `chipsBox`, `renderChips()`, перенос `chipsBox` между вкладками, ветка `data-chip` в делегированном обработчике |
| `page.js` | правило «`unchanged` гасит `changed`» |
| `cards.test.js` | четыре проверки `chips()` |

## Раскладка

| файл | что внутри |
|---|---|
| `labels.js` | `GROUPS` — описание групп обеих вкладок; `groups(tab)` собирает список, подставляя живые классы |
| `page.js` | трёхпозиционные фильтры, режимы групп, `filterState(key)`, `setFilter(key, state)`, `groupMode(id)`, `setGroupMode(id, mode)`, `filterCounts(tab)`, переписанные `stateMatches`/`diffMatches` |
| `hash.js` | новый ключ `any=` в `parse` и `format` |
| `filters.js` | новый: владелец кнопки и плашки меню — свой узел, свои слушатели, как `rail.js` |
| `filters.css` | новый: кнопка, плашка, заголовки групп, тройной переключатель |
| `cards.js` | `chips()` уходит; у плашки появляется вид «нет» |
| `ui.js` | заводит `filters`, теряет чипы |

`filters.js` встаёт в `SCRIPTS` между `cards.js` и `rail.js`; `filters.css`
— в `STYLES` между `table.css` и `toasts.css`.

## Тесты

**`page.test.js`** — ядро задачи, и проверяется без DOM:

- «есть» оставляет строки с признаком, «нет» — строки без него;
- два «есть» в режиме `все` требуют оба признака;
- те же два в режиме `любой из` — любой из них;
- «нет» действует и в режиме `любой из`: строка с этим признаком уходит;
- «есть» и «нет» на одном ключе невозможны — второе заменяет первое;
- пустой список «есть» в группе ничего не требует;
- ключ вне групп складывается по И;
- `unchanged` и `changed` вместе дают пересечение, а не заменяют друг друга;
- `filterCounts` считает по всем строкам вкладки, а не по видимым.

**`hash.test.js`** — `any=` разбирается и собирается; отсутствующий `any=`
приходит `null`, пустой — пустым списком; `f=` с минусами проходит насквозь
строками.

**`labels.test.js`** — группы вкладки, живые классы в группе `classes`,
пустая группа классов на чистой странице.

**`ui.test.js`** — кнопка показывает число условий; меню открывается и
закрывается кликом мимо и `Escape`; кнопка меню и плашка правят одно и то
же состояние; проверки, читавшие сейчас `#chips`, переезжают на подпись
кнопки.

Плюс снимок страницы в headless Firefox: сюиты не видят вёрстку, а
раскрытое меню — это вёрстка.
