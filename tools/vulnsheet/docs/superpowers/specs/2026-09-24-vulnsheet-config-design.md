# vulnsheet: конфиг и стримы VEX

**Дата:** 2026-09-24

Дополняет [основной спек](2026-09-24-vulnsheet-design.md). Там, где они
расходятся (обязательность `--rhel`/`--koji-url`/`--tag`, константы загрузки
VEX, стримы), действует этот документ.

## Задача

Для некоторых пакетов SberLinux собирается из модульного стрима Red Hat:
`nginx` у нас — это `nginx:1.26` у Red Hat. Сейчас `vulnsheet` спрашивает
VEX про обычный пакет `nginx` и получает вердикт не того продукта, либо
`not listed`.

Нужен конфиг, где для таких пакетов задан стрим VEX. Маппинг влияет только на
VEX: koji по-прежнему спрашивается про пакет из входа (`nginx`). Во входе
стримов не бывает — только имена пакетов.

Принцип сбора данных — **никаких откатов**. `--rhel 9` значит только RHEL 9,
не 9.2 и не другие минорные потоки. Компонент `nginx` значит только обычный
пакет `nginx`, не какой-либо из его стримов, — если только в конфиге для
этой версии RHEL он не сопоставлен стриму; тогда только этот стрим.

Заодно в конфиг выносится то, что сейчас приходится набирать флагами на
каждом запуске или что зашито в код константами.

## Конфиг

### Формат и поиск

YAML, как у `dashboard`. Файл задаётся `--config PATH` или переменной
окружения `VULNSHEET_CONFIG` (флаг главнее). Ни того, ни другого — конфига
нет, тулза работает на флагах и встроенных значениях, как раньше. Заданный,
но отсутствующий или нечитаемый файл — фатальная ошибка.

PyYAML (`python3-pyyaml`) импортируется только при заданном конфиге: без
конфига тулза по-прежнему требует только стандартную библиотеку и `koji`.
Не установлен PyYAML при заданном конфиге — фатальная ошибка с подсказкой,
какой пакет поставить.

### Содержимое

Все поля необязательные.

```yaml
koji:
  hub: https://koji.example.com/kojihub   # то же, что --koji-url
  tag: sl9-updates                        # то же, что --tag

rhel: "9"                                 # то же, что --rhel

vex:
  cache_dir: ~/.cache/vulnsheet           # ~ раскрывается
  cache_ttl: 3600                         # секунд, 0 — кэш не читать
  jobs: 8                                 # параллельных загрузок
  retries: 3                              # попыток на документ
  timeout: 30                             # секунд на запрос

# Стримы VEX по версиям RHEL: пакет из входа → стрим, как его пишет Red Hat.
vex_streams:
  "9":
    nginx: nginx:1.26
    npm: nodejs:20        # пакет внутри чужого модуля
  "10":
    nodejs: nodejs:22
```

Рядом с кодом лежит `vulnsheet.example.yaml` — этот же пример с
комментариями к каждому полю.

### Приоритет

Флаг командной строки > конфиг > значение в коде. Значения в коде — нынешние
константы: `cache_dir` — `$XDG_CACHE_HOME/vulnsheet` (по умолчанию
`~/.cache/vulnsheet`), `cache_ttl` 3600, `jobs` 8, `retries` 3, `timeout` 30.

`--rhel`, `--koji-url`, `--tag` перестают быть обязательными для argparse.
Если после сведения флагов и конфига какого-то из трёх нет — ошибка
аргументов (код 2) с текстом вида «нужен --tag или koji.tag в конфиге».

### Проверка

Любая ошибка ниже — `ConfigError`, одна строка в журнале с путём файла и
причиной, код 2, трейсбек только на `debug`:

- синтаксис YAML; корень — не словарь;
- неизвестный ключ на любом уровне (опечатка `cache_tll` не должна молча
  игнорироваться); в сообщении — полный путь ключа (`vex.cache_tll`);
- тип и границы: `koji.hub`, `koji.tag`, `vex.cache_dir` — непустые строки;
  `cache_ttl` — целое ≥ 0; `jobs`, `retries` — целые ≥ 1; `timeout` —
  число > 0; `bool` за число не принимается;
- `rhel` и ключи `vex_streams` — через ту же нормализацию, что `--rhel`
  (`9`, `"RHEL 9"`, `el9` → `9`; `9.2` остаётся `9.2`); YAML прочитает ключ
  `9:` без кавычек как число — это тоже принимается; две записи, дающие после
  нормализации одну версию, — ошибка;
- `vex_streams.<версия>` — словарь; пакет и стрим — непустые строки.

## Стримы VEX

### Выбор стрима

Для задачи с компонентом `P` при версии RHEL `R` стрим берётся из
`vex_streams` только из набора с ключом, точно равным `R`: для `--rhel 9.2`
читается только `"9.2"`, набор `"9"` к нему не применяется, и наоборот. В
наборе ищется `P` (точное совпадение). Нет набора или нет `P` в нём —
стрима нет, VEX спрашивается про обычный пакет.

### `vex.lookup(index, component, rhel, stream=None)`

- Без `stream` — только обычный пакет. Module/flatpak-стримы не
  учитываются никогда, даже если обычного пакета у Red Hat нет. Это меняет
  правило основного спека и старого скрипта, где стримы брались, когда
  ничего другого под этим именем не было.
- Без `stream`, если обычного пакета под этой версией нет, а стримы есть —
  `not listed (streams: nginx:1.24, nginx:1.26)`: маркер подсказывает, что
  нужен маппинг.
- Со `stream` — только продукты пакета `component`, чей стрим совпадает со
  `stream` целиком (`nginx:1.26`) или частью после двоеточия (`1.26`), как в
  старом скрипте. Обычный пакет в этом случае не учитывается.
- Пакет у Red Hat под этой версией RHEL есть, а нужного стрима нет —
  `not listed (streams: nginx:1.22, nginx:1.24)`; обычный пакет в этом
  списке — `(no stream)`. Маркер подсказывает, что маппинг устарел.
- Самый опасный вердикт, NVR фикса, дата, RHSA — как для обычного пакета.
- Версия RHEL сравнивается точно, как и раньше: продукты других минорных
  потоков в вердикт не попадают никогда. Если под `R` ничего нет, а в
  соседних минорных потоках того же мажора есть, маркер получает подсказку
  `not listed (present for 9.2, 9.4)`. Подсказки в маркерах — только
  объяснение, почему `not listed`; данных из других потоков и стримов в
  строку они не подставляют.

### Настройки загрузки

`vex.VexSettings` — неизменяемая запись `cache_dir`, `cache_ttl`, `jobs`,
`retries`, `timeout` со значениями по умолчанию, равными нынешним
константам. `fetch`, `fetch_all` и `download` получают настройки параметром;
о конфиге и файлах `vex` не знает.

## Что не меняется

- **koji** спрашивается про компонент из входа, стрим к нему не относится.
- **CSV**: в колонке `Компонент` — компонент из входа (`nginx`); куда
  смотрел VEX, видно в журнале.
- Формат входа, файл отбраковки, коды возврата.

## Устройство

Новый модуль `vulnsheet/config.py`:

- `Config` — неизменяемая запись: `path` (или `None`), `koji_hub`,
  `koji_tag`, `rhel`, `vex: VexSettings`, `vex_streams:
  Dict[str, Dict[str, str]]` (ключ — нормализованная версия RHEL).
- `load_config(path: Optional[str]) -> Config` — `None` даёт конфиг из
  встроенных значений; иначе читает и проверяет файл.
- `Config.stream_for(component, rhel) -> Optional[str]` — выбор стрима по
  правилу выше.

`cli.py`: `--config`; сведение флагов с конфигом; проверка трёх
обязательных значений; для каждой задачи — стрим из `Config.stream_for` в
`vex.lookup`. `vex` и `config` друг о друге не знают: связывает их только
`cli`.

## Журнал

- `info`: откуда конфиг (путь или «без конфига»); какие подмены стримов
  применились в этом прогоне и к скольким задачам — одной строкой, например
  «стримы VEX для RHEL 9: nginx → nginx:1.26 (3), npm → nodejs:20 (1)».
  Строки нет, если подмен не было.
- Пакеты из маппинга, которых нет во входе, в журнал не пишутся: конфиг
  общий, это нормально.
- `debug`: подмена для каждой пары CVE — компонент.

## Коды возврата

Добавляются случаи кода `2`: конфиг не найден, не читается, не проходит
проверку; PyYAML не установлен при заданном конфиге; после сведения нет
версии RHEL, хаба или тега.

## Тесты

- `test_config.py`: `load_config(None)` — встроенные значения; полный файл
  читается; `~` в `cache_dir` раскрывается; неизвестный ключ (с полным путём
  в сообщении); неверные типы и границы, `bool` вместо числа; ключ `9` без
  кавычек; дубль версии после нормализации; нечитаемый файл, синтаксис YAML;
  `stream_for` — точная версия; `--rhel 9.2` при наборе только для `"9"` —
  стрима нет (отката нет); `--rhel 9` при наборе только для `"9.2"` — стрима
  нет; пакета в наборе нет.
  Тесты `test_config.py` требуют PyYAML; без него они пропускаются
  (`skipUnless`), а не падают.
- `test_vex.py`: в одном документе обычный `nginx` (`Fixed`) и стрим
  `nginx:1.26` (`Affected`) — без стрима `Fixed`, со стримом `Affected`;
  короткая форма `1.26`; `npm` со стримом `nodejs:20`; нужного стрима нет →
  `not listed (streams: …)` с `(no stream)`; без маппинга, когда у Red Hat
  только стрим (`firefox::firefox:flatpak`), — `not listed (streams:
  firefox:flatpak)`, а не вердикт стрима; `VexSettings` доходит до
  `download` (timeout) и числа попыток.
- `test_cli.py`: сквозной прогон с конфигом — VEX получает стрим (вердикт
  стрима в CSV), koji — обычный `nginx`; хаб, тег и RHEL из конфига без
  флагов; флаг главнее конфига; `VULNSHEET_CONFIG`; нет ни флага, ни ключа →
  код 2; битый конфиг и отсутствующий файл → код 2 без трейсбека; строка
  подмен в журнале.
