# vulnsheet: обновление существующей таблицы

**Дата:** 2026-09-24

Дополняет [основной спек](2026-09-24-vulnsheet-design.md) и
[спек конфига](2026-09-24-vulnsheet-config-design.md). Там, где они
расходятся (позиционный вход, коды возврата), действует этот документ.

## Задача

Сейчас `vulnsheet` строит таблицу с нуля из блоков. Но таблицу потом ведут
люди: разработчик заполняет свои колонки, пишется комментарий. Перезапуск с
нуля эти данные теряет.

Нужны ещё два режима, которые берут существующую таблицу и обновляют её, не
трогая ручных колонок:

| Режим | На входе | Намерение |
|---|---|---|
| 1. Новая таблица | блоки | как сейчас: таблица с нуля |
| 2. Обновление koji и VEX | таблица | освежить данные koji и VEX, остальное не трогать |
| 3. Синхронизация с блоками | таблица и блоки | полностью обновить данные задач, koji и VEX; пропавшие задачи пометить, новые добавить |

## Группы колонок

Двадцать колонок `report.COLUMNS` делятся на группы:

| Группа | Колонки |
|---|---|
| Разработчик | Разработчик, Статус, Start date, End date, Принятая мера |
| Задача | Task ID, CVE ID, Task state, Task date, Исполнитель, Компонент |
| koji | SL NVR (latest build) |
| VEX | RHEL NVR (if fixed), Fix date, RHEL state, RHEL severity, RHEL CVSS, Advisory (RHSA) |
| Ссылка | CVE link |
| Комментарий | Комментарий |

Что с группой делает каждый режим:

| Группа | Режим 1 | Режим 2 | Режим 3: строка совпала | Режим 3: `Missing` | Режим 3: новая строка |
|---|---|---|---|---|---|
| Разработчик | `-` | как есть | как есть | как есть | `-` |
| Задача | из блока | как есть | из блока | как есть, `Task state` → `Missing` | из блока |
| koji | koji | koji | koji | koji | koji |
| VEX | VEX | VEX | VEX | VEX | VEX |
| Ссылка | по CVE | по CVE | по CVE | по CVE | по CVE |
| Комментарий | `-` | как есть | как есть | как есть | `-` |

«Как есть» — ячейка дословно из входной таблицы, без нормализации.

### Сбои сети

У строки, которая уже была в таблице:

- koji вернул `ERROR` — остаётся прежний `SL NVR`;
- VEX дал `fetch error` — остаются прежние значения всей группы VEX.

Такие строки перечисляются в журнале (`warning`), код возврата 1. У новых
строк режима 3 прежних значений нет — пишется маркер, как в режиме 1.

`NOT_FOUND` и `not listed …` — не сбой, а ответ; они перезаписывают прежние
значения.

### Строки, по которым нечего спрашивать

Строка таблицы, где `CVE ID` после обрезки пробелов и перевода в верхний
регистр не CVE-ID (`tasks.CVE_RE`), или `Компонент` пустой либо `-`,
остаётся **целиком** без изменений во всех режимах, в режиме 3 — и без
`Missing`: такая строка ни с чем не сопоставляется. В журнале —
`warning` с номером записи, CVE и компонентом; код возврата 1.

### Стримы VEX

Маппинг `vex_streams` из конфига действует во всех режимах одинаково: по
компоненту строки и `--rhel`. koji спрашивается про компонент строки.

## Режим 3: сопоставление

Ключ строки и блока — тройка (Task ID, CVE ID, Компонент). Для сравнения
`Task ID` и `Компонент` обрезаются по краям, `CVE ID` ещё и переводится в
верхний регистр; в ячейки нормализованные значения не пишутся (кроме тех,
что приходят из блока в совпавшую строку).

- Строка таблицы с тройкой из блоков — **совпала**: группа «Задача» берётся из
  блока, koji и VEX обновляются.
- Строка таблицы, чьей тройки нет в блоках, — **Missing**: в `Task state`
  пишется `Missing`, остальная группа «Задача» как есть, koji и VEX
  обновляются. Строка не удаляется.
- Тройка из блоков, которой нет в таблице, — **новая строка** в конце
  таблицы, после всех существующих, в порядке блоков.
- Порядок существующих строк не меняется.
- Строка, помеченная `Missing` в прошлый раз и снова появившаяся в блоках, —
  обычная совпавшая: `Task state` из блока.

Дубли допустимы:

- одна тройка в нескольких блоках — действует первый блок, остальные
  игнорируются (в журнале `info` с числом); новая тройка добавляется
  одной строкой;
- одна тройка в нескольких строках таблицы — каждая такая строка
  сопоставляется с блоком (или становится `Missing`) самостоятельно.

Битые блоки, как в режиме 1, идут в файл отбраковки и дают код 1. Строки
таблицы, чей блок оказался битым, получают `Missing` как обычно: битый блок
виден в отбраковке и по коду возврата.

Режим 1 не меняется: дубль блока по-прежнему даёт дубль строки.

## Чтение таблицы

Таблица — файл в формате, который пишет сам `vulnsheet`:

- UTF-8, BOM в начале допускается;
- разделитель `;`, кавычки по правилам CSV (модуль `csv`);
- первая запись — заголовок, равный `report.COLUMNS` целиком;
- каждая следующая запись — ровно 20 ячеек; полностью пустые записи
  пропускаются.

Фатальная ошибка (код 2, в сообщении путь и номер записи, заголовок — запись
1): файл не читается, не UTF-8, пустой, заголовок не тот, в записи не 20
ячеек. Выбросить «кривую» строку нельзя — в ней ручные данные.

Таблица из одного заголовка допустима: режим 2 выдаёт такую же пустую
таблицу, в режиме 3 все блоки становятся новыми строками.

## CLI

Позиционный аргумент убирается; вход задаётся флагами:

| Флаг | Значение |
|---|---|
| `--blocks FILE` | файл с блоками; `-` — stdin |
| `--table FILE` | существующая таблица; только файл, `-` не принимается |

Режим определяется по флагам: только `--blocks` — 1, только `--table` — 2,
оба — 3. Ни одного — ошибка аргументов, код 2.

- `-o` может совпадать с `--table`: запись атомарная, при сбое прогона
  прежняя таблица остаётся нетронутой.
- Файл отбраковки ведётся только при `--blocks` (режимы 1 и 3). В режиме 2
  старый файл отбраковки не трогается.
- Нет ни одного блока во входе (ни целых, ни битых) — фатальная ошибка в
  режимах 1 и 3: в режиме 3 иначе все строки молча стали бы `Missing`.
- В режиме 3 блоки есть, но все битые (годных нет) — тоже фатальная ошибка,
  по той же причине: иначе синхронизация молча пометила бы `Missing` вообще
  все строки таблицы.
- Остальные флаги (`--config`, `--rhel`, `--koji-url`, `--tag`,
  `--rejects`, `--log-level`, `--version`) — как раньше.

Порядок работы: конфиг и настройки → таблица и блоки (все ошибки чтения
до сети) → открытие выхода → koji и VEX по всем парам итоговой таблицы →
слияние → запись.

Спрашиваются только нужные данные: CVE и пакеты всех строк, которые будут
обновлены (строки «нечего спрашивать» не участвуют).

## Журнал

- `info`: режим (`режим: новая таблица`, `режим: обновление koji и VEX`,
  `режим: синхронизация с блоками`);
- `info` в режимах 2 и 3: `таблица old.csv: строк N`;
- `info` в режиме 3: `совпало N, Missing M, новых K`; повторы троек в блоках —
  числом, если есть;
- `warning`: строки, где при сбое оставлены прежние koji или VEX, и строки,
  по которым нечего спрашивать — номер записи, CVE, компонент;
- строка о стримах и итоговая сводка RHEL state и SL NVR — как сейчас, по
  всем строкам выхода.

## Коды возврата

- `0` — всё хорошо. `Missing` сам по себе не ошибка.
- `1` — CSV записан, но есть битые блоки, `fetch error`, koji `ERROR`
  (в том числе там, где оставлены прежние значения) или строки, по которым
  нечего спрашивать.
- `2` — фатальная ошибка, как раньше, плюс ошибки таблицы, нет ни
  `--blocks`, ни `--table`, пустые блоки.

## Устройство

- `report.py` — группы колонок как индексы в `COLUMNS` и константа
  `MISSING = "Missing"`; `row()` не меняется.
- `table.py` (новый) — `read(path) -> List[Record]` (`Record` — номер записи
  и ячейки) и `TableError`.
- `merge.py` (новый) — чистые функции без ввода-вывода и сети: по строкам
  таблицы, задачам и готовым ответам koji и VEX строят итоговые строки и
  счётчики для журнала. Свежая строка строится `report.row()`, затем из
  старой строки переносятся группы по таблице выше. Для строки таблицы
  «задача» собирается из её ячеек.
- `cli.py` — флаги, выбор режима, сбор пар для koji и VEX, вызов `merge`,
  журнал, коды возврата.

## Тесты

- `test_table.py`: чтение; BOM; ячейка с `;` в кавычках сохраняется
  дословно; неверный заголовок; запись из 19 и 21 ячейки; пустой файл;
  только заголовок; пустые записи пропускаются; не UTF-8.
- `test_merge.py`:
  - режим 2: ручные колонки и группа «Задача» не меняются, koji и VEX
    обновляются; `ERROR`/`fetch error` оставляют прежние значения;
    `NOT_FOUND`/`not listed` перезаписывают; строка с `-` в CVE целиком
    без изменений;
  - режим 3: совпадение, `Missing`, новые строки в конце в порядке блоков,
    порядок существующих; сравнение CVE без учёта регистра и пробелов;
    `Missing`, вернувшийся в блоки; дубли в блоках и в таблице; у новой
    строки при сбое — маркер.
- `test_cli.py`: три режима сквозным прогоном на фейках; `-o` совпадает с
  `--table`; нет ни одного из флагов → 2; пустые блоки в режиме 3 → 2;
  битая таблица → 2 без трейсбека, прежний выход цел; отбраковка в режиме 2
  не трогается; `--blocks -` читает stdin.
