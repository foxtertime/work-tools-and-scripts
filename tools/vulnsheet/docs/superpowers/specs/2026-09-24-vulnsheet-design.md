# vulnsheet: таблица задач по уязвимостям с данными RHEL и koji

**Дата:** 2026-09-24

Конфиг и стримы VEX описаны отдельно —
[2026-09-24-vulnsheet-config-design.md](2026-09-24-vulnsheet-config-design.md);
где документы расходятся, действует тот.

## Задача

Задачи на устранение уязвимостей приходят из тасктрекера текстом — блоками по
шесть строк. Чтобы превратить их в рабочую таблицу, сейчас по очереди
запускают три скрипта: `tocsv.py` разбирает блоки, `vex.py` спрашивает у
Red Hat CSAF/VEX статус CVE для компонента в RHEL, `latest.py` спрашивает у
koji последний билд компонента в теге. Результаты сводятся вручную.

`vulnsheet` делает это одним запуском: принимает блоки, версию RHEL, URL
koji-хаба и тег, и пишет CSV из двадцати колонок в том виде, в каком таблицу
ведёт процесс.

Доступ к koji — только на чтение. В названиях файлов и модулей нет слова
«cve».

## Что не меняется относительно старых скриптов

- **Логика интерпретации VEX** переносится из `vex.py` с его значениями по
  умолчанию: точное совпадение имени компонента; module/flatpak-стримы не
  считаются компонентом, если есть обычный пакет; `-debuginfo`/`-debugsource`
  отбрасываются; эпоха в NVR срезается; при нескольких вердиктах под одной
  версией RHEL побеждает самый опасный (`Affected` < `Fix deferred` <
  `Will not fix` < `Out of support scope` < `Under investigation` < `Fixed` <
  `Not affected`); отсутствие компонента в VEX — не «Not affected», а
  `not listed`, с подсказкой про соседние минорные стримы.
- **Источник VEX** — `https://security.access.redhat.com/data/csaf/v2/vex/<год>/<cve>.json`,
  404 означает «у Red Hat записи нет».
- **Запрос к koji** — `getLatestBuilds(tag, package=…)` пакетно через
  `multicall`, по одному разу на уникальный пакет.

Флаги `vex.py` кроме `--rhel` не переносятся: их значения по умолчанию и есть
нужное поведение, а формат таблицы фиксирован процессом.

## Устройство

```text
tools/vulnsheet/
├── README.md  TODO.md  CHANGELOG.md
├── pyproject.toml  setup.cfg
├── vulnsheet/
│   ├── __init__.py    # __version__
│   ├── __main__.py    # python3 -m vulnsheet
│   ├── cli.py         # аргументы, связывание модулей, коды возврата
│   ├── logs.py        # единственное место, где ставится хендлер логов
│   ├── tasks.py       # разбор блоков входа
│   ├── kojiclient.py  # latest-билды тега
│   ├── vex.py         # загрузка CSAF с кэшем и интерпретация
│   └── report.py      # строка таблицы и запись CSV
├── tests/
└── docs/superpowers/
```

Упаковка — как у `dashboard`: метаданные в `setup.cfg`, в `pyproject.toml`
только `[build-system]` (в RHEL 9 стоит setuptools 53, `[project]` он не
понимает). Номер версии — в `vulnsheet/__init__.py`, `setup.cfg` читает его
через `attr:`. Точка входа `console_scripts`: `vulnsheet = vulnsheet.cli:main`.
Запуск без установки — `python3 -m vulnsheet`.

Зависимости: стандартная библиотека и `koji`. `koji` в метаданных не
перечислен — ставится системным пакетом — и импортируется только внутри
`kojiclient`, чтобы остальное (разбор, отчёт, тесты) работало без него.

Каждый модуль пишет через `logging.getLogger(__name__)`; хендлеры ставит
только `cli` через `logs.configure`.

### Поток данных

1. `tasks.parse(text)` → `(tasks, rejects)`: список `Task` в порядке входа и
   список отбракованных блоков.
2. Уникальные компоненты из `tasks` → `kojiclient.latest_builds(hub, tag,
   packages)` → `{пакет: NVR | NOT_FOUND | ERROR}`.
3. Уникальные CVE из `tasks` → `vex.fetch_all(cves)` в пуле из 8 потоков, с
   кэшем → `{cve: документ | None | ошибка}`.
4. Для каждой задачи `vex.lookup(doc, component, rhel)` → `Verdict`.
5. `report.row(task, nvr, verdict)` → строка из 20 ячеек; `report.write(rows,
   fh)` пишет CSV. Порядок и дубликаты входа сохраняются.
6. `rejects` пишутся в файл отбраковки (см. ниже).

## Модули

### `tasks.py`

`Task` — неизменяемая запись: `task_id`, `cve`, `component`, `state`, `date`,
`assignee`.

Разбор:

- Вход делится на блоки по пустым строкам (строка из одних пробельных
  символов тоже пустая). Других разделителей нет: строка `---` — обычная
  строка блока.
- Строки блока обрезаются по краям; `\r\n` обрабатывается как `\n`.
- Корректный блок — ровно шесть строк:
  1. тип связи (`Состоит из`) — не используется;
  2. Task ID — как есть;
  3. `CVE-ГГГГ-N… компонент` — делится по первому пробельному промежутку; CVE
     приводится к верхнему регистру и должен соответствовать
     `^CVE-\d{4}-\d{4,}$`; компонент — непустой остаток;
  4. Task state — как есть;
  5. Task date — как есть;
  6. Исполнитель — как есть.
- Блок отбраковывается, если в нём не шесть строк, третья строка не
  начинается с CVE-ID или в ней нет компонента. `Reject` хранит номер блока
  (с единицы), исходный текст блока дословно и причину.

### `kojiclient.py`

`latest_builds(hub_url, tag, packages) -> dict[str, str]`.

- Одна `koji.ClientSession(hub_url)`, один `multicall(strict=False)` на все
  уникальные пакеты.
- Найден билд — его `nvr`; пустой ответ — `NOT_FOUND`; ошибка koji по
  конкретному пакету — `ERROR` (warning в лог с текстом ошибки).
- Перед запросом билдов — `getTag(tag)`: тега нет — `KojiError` («нет тега
  …»), а не таблица из одних `ERROR`.
- Хаб недоступен целиком (исключение на `getTag` или на самом `multicall`),
  модуль `koji` не установлен — исключение `KojiError` наружу, `cli`
  превращает его в фатальную ошибку.
- Если годных задач нет (всё отбраковано), к koji не обращаемся вовсе.
- Пакеты с `NOT_FOUND` перечисляются одной warning-строкой.
- `debug`: хаб, число пакетов, длительность вызова.

### `vex.py`

- `fetch(cve)` — документ, `None` при 404 или исключение после трёх попыток
  с паузами 1 и 2 с. Кэш — `~/.cache/vulnsheet/<cve>.json` (с учётом
  `XDG_CACHE_HOME`), время жизни
  1 час; запись атомарная, битая или недоступная запись кэша игнорируется,
  ошибка создания каталога кэша отключает кэш с warning.
- `fetch_all(cves)` — пул из 8 потоков; возвращает `{cve: документ | None}` и
  `{cve: текст ошибки}`. `info`: прогресс примерно на каждые 10 % CVE.
  `debug`: URL, код ответа, длительность, попадания в кэш.
- `lookup(doc, component, rhel) -> Verdict` — логика `vex.py.lookup` с
  фиксированными значениями бывших флагов. `Verdict`: `state`, `severity`,
  `cvss`, `fixed_nvr`, `fix_date` (ISO), `advisory_url`. Пояснения, которые
  `vex.py` печатал как `note:` (проигнорированные стримы, несколько
  вердиктов, соседние минорные стримы с другим вердиктом), идут в лог на
  уровне `debug`.
- Версия RHEL нормализуется как в `vex.py`: `RHEL 9`, `rhel-9`, `el9` → `9`;
  `9.2` остаётся `9.2`. Невалидная версия — ошибка аргументов.

### `report.py`

Колонки, в этом порядке, заголовок — первая строка CSV:

| # | Колонка | Значение |
|---|---|---|
| 1 | `Разработчик` | `-` |
| 2 | `Статус` | `-` |
| 3 | `Start date` | `-` |
| 4 | `End date` | `-` |
| 5 | `Принятая мера` | `-` |
| 6 | `Task ID` | из входа |
| 7 | `CVE ID` | из входа |
| 8 | `Task state` | из входа |
| 9 | `Task date` | из входа |
| 10 | `Исполнитель` | из входа |
| 11 | `Компонент` | из входа |
| 12 | `SL NVR (latest build)` | koji: NVR / `NOT_FOUND` / `ERROR` |
| 13 | `RHEL NVR (if fixed)` | VEX, только при `Fixed`; несколько — через `\|` |
| 14 | `Fix date` | VEX, только при `Fixed`; `dd.mm.yyyy` |
| 15 | `RHEL state` | VEX, см. ниже |
| 16 | `RHEL severity` | VEX |
| 17 | `RHEL CVSS` | VEX |
| 18 | `Advisory (RHSA)` | VEX, только при `Fixed`; полный URL errata |
| 19 | `CVE Link` | `https://access.redhat.com/security/cve/<CVE ID>` |
| 20 | `Комментарий` | `-` |

`RHEL state` — одно из: `Fixed`, `Affected`, `Will not fix`, `Fix deferred`,
`Out of support scope`, `Under investigation`, `Not affected` (или иной текст
из `details` ремедиации, как его отдаёт Red Hat); маркеры `not listed`,
`not listed (present for 9.2, 9.4)`, `no VEX record`, `fetch error`.

- Любая пустая ячейка — `-`. Пустой — только `None` и `""`: CVSS `0.0`
  сохраняется.
- Дата фикса из VEX (`2026-09-02` или `2026-09-02T…`) → `02.09.2026`;
  нераспознанная дата пишется как есть.
- CSV: UTF-8 без BOM, разделитель `;`, строки через `\n`, кавычки —
  по правилам модуля `csv` (только там, где нужны).

Пример из задания даёт строку:

```text
-;-;-;-;-;TASKID-181229;CVE-2026-73070;Отменен;22.09.2026;КМ;vim;vim-8.2.2637-26.sl9_8.6^4;-;-;Under investigation;Moderate;5.5;-;https://access.redhat.com/security/cve/CVE-2026-73070;-
```

### Файл отбраковки

- Битые блоки в CSV не попадают. Они пишутся в файл дословно, как во входе,
  через пустую строку — исправленный файл можно подать на вход повторно.
- Причина в файл не пишется; она уходит в лог warning-строкой: номер блока,
  его первая строка, причина.
- Путь — `--rejects PATH`. По умолчанию: при `-o report.csv` —
  `report.rejected.txt` рядом (расширение выхода заменяется, а без
  расширения — дописывается `.rejected.txt`); при выводе в stdout —
  `vulnsheet.rejected.txt` в текущем каталоге.
- Файл создаётся только если битые блоки есть. Если их нет, а файл по этому
  пути остался от прошлого прогона, он удаляется (`info` в лог).

### `cli.py`

```bash
python3 -m vulnsheet --rhel 9 --koji-url https://koji.example.com/kojihub \
    --tag sl9-updates tasks.txt -o report.csv
```

| Аргумент | Смысл |
|---|---|
| `input` | файл с блоками; без него или `-` — stdin |
| `--rhel` | версия RHEL, обязательный |
| `--koji-url` | URL kojihub, обязательный |
| `--tag` | koji-тег, обязательный |
| `-o`, `--output` | CSV; без него — stdout |
| `--rejects` | файл отбраковки (см. выше) |
| `--log-level` | `error` / `warning` / `info` / `debug`, по умолчанию `info` |
| `--version` | печатает `vulnsheet <версия>` |

Порядок: разбор аргументов → чтение входа → проверка каталогов выхода и (если
указан явно) `--rejects` (до сети, чтобы неверный путь падал сразу) → koji →
VEX → запись CSV → файл отбраковки → сводка. Файл выхода при этом не
открывается на запись сразу: CSV пишется во временник рядом с ним, и только
после успешной записи временник атомарно (`os.replace`) подменяет собой
прежний файл — неудачный прогон не должен стирать вчерашний отчёт.

### `logs.py`

Копия подхода `dashboard` (свой код, не общий): один `StreamHandler` в
stderr на логгер `vulnsheet`, `propagate = False`, повторный `configure`
заменяет хендлер. Формат `HH:MM:SS LEVEL   модуль: сообщение`, имя модуля
без `client` (`kojiclient` → `koji`); на `debug` добавляется имя потока.

| Уровень | Что видно |
|---|---|
| `error` | фатальная ошибка — одна строка |
| `warning` | битые блоки, пакеты `NOT_FOUND`, `ERROR` koji по пакету, ошибки загрузки VEX по CVE, отключённый кэш |
| `info` | параметры прогона (хаб, тег, RHEL), число блоков / отбракованных / уникальных CVE / уникальных пакетов, прогресс VEX, сводка по `RHEL state` и по `SL NVR` (найдено / `NOT_FOUND` / `ERROR`), записанные файлы, общее время |
| `debug` | запросы к VEX и koji, попадания в кэш, пояснения к вердиктам, трейсбек фатальной ошибки |

## Коды возврата

| Код | Когда |
|---|---|
| `0` | CSV записан, ошибок нет. `NOT_FOUND` и `not listed` ошибками не считаются — это ответ источника |
| `1` | CSV записан, но есть отбракованные блоки, `ERROR` от koji или `fetch error` VEX |
| `2` | фатально: неверные аргументы, вход не читается или в нём нет ни одного блока, выход не пишется, хаб koji недоступен целиком, непредвиденное исключение |

Ошибки аргументов argparse возвращает своим кодом `2` — совпадает.

## Тесты

`unittest`, без сети; запуск из каталога тулзы — `python3 -m unittest`.
koji подменяется поддельной сессией с `multicall`, VEX — функцией загрузки,
отдающей маленькие CSAF-документы; собирает их функция `csaf()` из
`tests/fakes.py`, чтобы в каждом тесте было видно, из чего состоит документ.
Кэш VEX в тестах уводится во временный каталог через `XDG_CACHE_HOME`
(каталог кэша — `$XDG_CACHE_HOME/vulnsheet`, по умолчанию
`~/.cache/vulnsheet`).

- `test_tasks.py` — блок из задания; несколько блоков; лишние пробелы, `\r\n`,
  пробельная «пустая» строка; блок из 5 и 7 строк, строка `---` внутри
  блока, третья строка без компонента, не-CVE → отбраковка с причиной и
  дословным текстом; пустой вход.
- `test_kojiclient.py` — каждый пакет запрашивается один раз; найденный /
  `NOT_FOUND` / `ERROR` по пакету; недоступный хаб → `KojiError`.
- `test_vex.py` — `Fixed` с NVR, датой и RHSA; `Affected` с `Will not fix`
  из ремедиации; `Under investigation`; flatpak-стрим игнорируется при
  наличии обычного пакета; `not listed (present for 9.2)`; несколько
  вердиктов → самый опасный; эпоха срезается; 404 → `no VEX record`; битый
  файл кэша не мешает загрузке.
- `test_report.py` — 20 колонок в порядке и с точными заголовками; прочерки;
  `dd.mm.yyyy`; NVR/дата/RHSA только при `Fixed`; CVSS `0.0` сохраняется.
- `test_cli.py` — сквозной прогон примера из задания даёт ровно строку
  выше; файл отбраковки создаётся, путь по умолчанию считается от `-o`,
  старый файл удаляется; коды 0/1/2; `--version`.
- `test_version.py` — у текущей версии есть запись в `CHANGELOG.md` тулзы.
