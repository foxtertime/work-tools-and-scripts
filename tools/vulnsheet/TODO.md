- [ ] **BUG-H-2610-02**
      Область: `merge.py`, `_comment_note`, `_updated`; `report.py`, `with_patch_note`.
      С включённой секцией `ranges` сбой GitLab стирает прежние ссылки на патчи
      (и наоборот). Фрагменты о патчах и о диапазоне склеиваются в одну пометку,
      а `with_patch_note` убирает все свои старые фрагменты и ставит новую.
      Диапазон даёт фрагмент почти каждой строке с билдом, поэтому при сбое
      GitLab по компоненту (сеть, просроченный токен, `FAILED`) прежние «патч
      найден: …» и «спек, …» молча пропадают, остаётся только «версия … (NVD)».
      Это противоречит README («Ошибка — код 1, ячейка не меняется»; «пометку
      прошлого прогона тулза не снимает»). Воспроизведено: `merge.refresh` с
      пустым `patched` и `RangeNote` — `ждём апстрим; патч найден: https://g/x.patch`
      → `ждём апстрим; версия 1.26.3 в уязвимом диапазоне <1.27 (NVD)`, итог
      считает это «обновлена». Предложено: заменять фрагменты по семействам —
      патчи (PATCH и спек) и диапазон; семейство, по которому в этом прогоне
      данных нет, оставлять как было. Тогда уходит и оговорка README «фрагмент о
      диапазоне пропадает после сбоя». Тест: «GitLab упал, диапазон есть —
      старая ссылка на патч цела» и обратный.
      Источник: ревью 1.1.0–1.6.1 (2026-10-16).
      Приоритет высокий (2026-10-16): тихая потеря данных в ячейке при любом
      сбое GitLab или NVD; таблица перезаписывается на месте.

      Область: `ranges.py`, `_cveorg_interval`.
      Неразобранный текст версии из CVE.org становится «точкой», и тулза пишет
      ложное «вне уязвимого диапазона». Всё, что не начинается с `<>=` и не в

      `^\d[\w.+~^-]*$` без пробелов; `X.*`/`X.x` — либо верхняя граница
      префикса, либо отбрасывать; остальное отбрасывать, чтобы вышло честное
      «диапазон неизвестен». Фикстуры по реальным форматам CNA — см.
      DEBT-2610-04.
      Источник: ревью 1.1.0–1.6.1 (2026-10-16).
      Приоритет средний (2026-10-16): ложное «вне диапазона» читается как повод
      снизить приоритет задачи.

- [ ] **BUG-M-2610-05**
      Область: `ranges.py`, `_affected_intervals`, `_cveorg_interval`.
      CVE.org: не учитываются `versionType: git` и `defaultStatus: affected`
      (формат CNA ядра Linux). Пропускаются только `rpm` и `unaffected`, поэтому
      интервалы из git-хешей попадают в сравнение; одиночное `{"version":
      "2.6.12", "status": "affected"}` при `defaultStatus: affected` значит «с
      2.6.12 и дальше, кроме unaffected-диапазонов», а читается как точка.
      Воспроизведено (документ той же структуры, что у CNA ядра): интервалы
      `=2.6.12` и `>=1da177e4… <9f6ad5d5…`. Срабатывает при алиасе `kernel:
      linux` в `ranges.names`, когда NVD свежую CVE ядра ещё не разобрал.
      Предложено: пропускать `versionType` из `{"git", "rpm",
      "original_commit_for_fix"}`; для `defaultStatus: affected` строить
      дополнение unaffected-диапазонов, а до того — отдавать «неизвестен».
      Источник: ревью 1.1.0–1.6.1 (2026-10-16).
      Приоритет средний (2026-10-16): неверный диапазон для ядра и других CNA
      того же формата.
