# taskhistory: история задач по снимкам

Решение одобрено пользователем, 2026-10-31.

## Задача

Пользователь сохраняет несколько снимков задач Jira в формате шестистрочных
блоков, который читает vulnsheet. Нужно получить файл с задачами по каждому
исполнителю: когда задача замечена взятой в работу, когда завершённой,
что произошло при передаче, повторном открытии или исчезновении из снимка.
Нужен фильтр по заданным пользователем инициалам.

Дата внутри блока — дата создания задачи. Даты наблюдений берутся только
из имён файлов: например, `input-28-10-2026.txt`.

## Подход

Предложение: самостоятельная CLI-тулза `tools/taskhistory/` на Python 3.9+
без сторонних зависимостей, с CSV-отчётом. Это соответствует устройству
репозитория: каждую тулзу можно скопировать целиком. Разбор того же формата
реализуется локально, без импорта соседнего vulnsheet.

Рассмотренные альтернативы:

- Подкоманда vulnsheet: проще переиспользовать парсер, но история задач
  не требует koji, VEX и остальных возможностей vulnsheet; пользователь
  запросил отдельную тулзу.
- Загрузка снимков в базу с накоплением истории: полезна для постоянного
  сервиса, но для разового сравнения нескольких файлов создаёт лишнее
  состояние. В первой версии каждый запуск полностью определяется входами.

Python, название тулзы и CSV предложены исполнителем и приняты вместе
со спецификацией. Правила взятия и завершения уточнены пользователем.

## Вход и CLI

```sh
cd tools/taskhistory
python3 -m taskhistory input-21-10-2026.txt input-28-10-2026.txt input-31-10-2026.txt \
    --assignee КМ --assignee АБ -o history.csv
```

- Два или больше файлов позиционными аргументами, порядок произвольный.
- Дата в имени: единственная подстрока `DD-MM-YYYY`, ограниченная
  нецифровыми символами или границами имени. Каталоги не учитываются.
- Файлы сортируются по дате. Невозможная дата, отсутствие даты, несколько
  дат в имени, одинаковые даты у разных входов и повторный вход — ошибки.
  В первой версии сравниваются снимки разных дней, без времени суток.
- `--assignee` повторяется для каждого нужного исполнителя. По краям
  убираются пробелы, сравнение без учёта регистра; отображение берётся
  из входа. Без флага выводятся все исполнители, включая `Без исполнителя`
  для прочерка. Для выбора этой группы используется `--assignee -`.
- Фильтр применяется после построения полной истории, чтобы видеть передачи.
  Неизвестные фильтру инициалы дают предупреждение; при отсутствии совпадений
  формируется корректный CSV только с заголовком.
- `-o/--output` обязателен; `--version` выводит версию.
- Выход не может совпадать ни с одним входом, в том числе через ссылку.

Каждый блок содержит шесть непустых строк: служебная строка, ID задачи,
CVE и компонент, статус, дата создания, инициалы. Пустая строка разделяет
блоки. UTF-8 с BOM и CRLF допускаются. Дата создания сохраняется как текст.
ID задачи обязателен. CVE проверяется по правилам vulnsheet.

Идентификатор истории — ID задачи с удалёнными краевыми пробелами,
без учёта регистра. Полностью совпадающие повторные блоки одного снимка
объединяются с предупреждением. Различающиеся блоки одного ID — ошибка:
нельзя молча выбрать другого исполнителя или статус. CVE и компонент в
отчёте — последние наблюдавшиеся для соответствующего периода.

Битый блок, пустой файл и неизвестный статус — ошибки с именем файла
и номером блока. До успешной проверки всех входов выход не меняется.
Пустой снимок в первой версии не поддерживается: невозможно отличить
пустую выгрузку от неудачного копирования.

## Статусы

Подтверждённый пользователем набор: `В работу`, `В работе`, `Выполнен`,
`Отменен`, `Решен`. Последние три считаются завершением, включая отмену.
Краевые пробелы и регистр не влияют на классификацию; `ё` равнозначна `е`.

Правила пользователя:

- Взятие в работу — появление инициалов человека вместо инициалов другого
  исполнителя (или прочерка), независимо от статуса.
- Переходы между `В работу` и `В работе` при прежнем исполнителе
  не означают нового взятия.
- Завершение — переход из незавершённого статуса в `Выполнен`, `Отменен`
  или `Решен`. Смена одного завершённого статуса на другой — не новое
  завершение.

Датой события служит дата снимка, на котором оно впервые наблюдается.
Это дата наблюдения, а не установленная точная дата перехода в Jira.

## Правила истории

- Одна строка отчёта — один непрерывный период задачи у исполнителя.
  Повторное открытие после завершения начинает новую строку даже у того
  же исполнителя. Порядковый номер периода относится к задаче в целом.
- Первое наблюдение задачи создаёт строку с датой первого наблюдения
  у исполнителя, без даты взятия: прежние инициалы неизвестны.
  Примечание: «Первое наблюдение; дата взятия неизвестна». Если задача
  уже завершена, дата завершения тоже неизвестна и остаётся пустой;
  примечание об этом добавляется независимо от номера снимка.
- Переход в завершённый статус заполняет завершение текущего периода.
  Смена одного завершённого статуса на другой остаётся в той же строке;
  дата первого наблюдения завершения сохраняется, последний статус обновляется.
- Повторные наблюдения неизменного состояния не меняют даты событий.
- При передаче исполнителю текущая строка заканчивается с причиной
  «Передана исполнителю …», новая принадлежит новому исполнителю
  и получает дату взятия по текущему снимку. Передача на прочерк означает
  снятие исполнителя: строка группы «Без исполнителя» не получает дату взятия.
  Завершение не приписывается предыдущему исполнителю. Если одновременно
  изменились исполнитель и статус из незавершённого на завершённый, завершение отражается
  у нового исполнителя с примечанием о том, что передача и завершение
  впервые видны в одном снимке и порядок событий неизвестен.
  Если задача до и после передачи завершённая, новое завершение
  не создаётся. Первое наблюдаемое завершение остаётся у прежнего исполнителя.
- Переходы между `В работу` и `В работе` отражаются в истории, но
  не начинают новый период и не меняют дату взятия.
- Возврат из завершённого статуса в любой незавершённый создаёт новый
  период с пометкой «Повторно открыта»; прежнее завершение сохраняется.
  При прежнем исполнителе дата нового взятия пустая: инициалы не менялись.
  Если одновременно изменился исполнитель, новый период один и дата взятия
  заполняется по правилу передачи.
- Отсутствие задачи в следующем снимке заканчивает наблюдаемый период
  с причиной «Нет в снимке», без даты завершения задачи. Если задача
  появляется снова, создаётся новый период с пометкой «После отсутствия».
  Сравнение исполнителя и статуса ведётся с последним наблюдением этой
  задачи до исчезновения: другие инициалы дают взятие, прежние — нет;
  переход из незавершённого в завершённый даёт завершение. В примечании
  указан разрыв наблюдений. Смена статуса на завершённый у прежнего
  исполнителя после разрыва не стирает его ранее наблюдавшееся взятие:
  оно остаётся в предыдущем периоде, а связь видна по ID задачи и истории.
- У последнего периода задачи, присутствующей в последнем снимке,
  окончание наблюдения — дата последнего снимка, причина — «Последний снимок».
- В отдельном поле истории сохраняются даты изменений статуса и исполнителя,
  а также исчезновения и повторного появления. Даты создания к ним не относятся.
- Промежуточные события между снимками, которых нет во входных данных,
  не восстанавливаются. Примечания сохраняют ограничения первого снимка
  и одновременных изменений, чтобы не выдавать наблюдения за точные переходы.

## Отчёт

CSV: UTF-8 с BOM для открытия в табличном редакторе, разделитель `;`,
экранирование средствами стандартного модуля `csv`.

Колонки:

1. Исполнитель.
2. Task ID.
3. CVE ID.
4. Компонент.
5. Дата создания.
6. Период.
7. Впервые у исполнителя (снимок).
8. Взята в работу (снимок).
9. Завершена (снимок).
10. Последний статус.
11. Наблюдалась до (снимок).
12. Причина окончания периода.
13. История изменений.
14. Примечание.

Строки группируются сортировкой по инициалам, затем ID задачи и номеру
периода. Неизвестные даты — пустые ячейки. Неизменная задача занимает
одну строку независимо от числа снимков. Границы периода — границы
наблюдений: при передаче или исчезновении поле «Наблюдалась до» хранит
дату предыдущего снимка, а в истории указана дата снимка, выявившего изменение.

Запись атомарная во временный файл рядом с выходным, с последующей заменой.
Ошибки чтения и проверки не портят предыдущий отчёт. Ошибки и краткая
сводка идут в stderr; успешный запуск — код 0, ошибка — код 2.

## Проверка и документация

Тесты стандартным `unittest`: парсер блоков и имён, сортировка снимков,
базовый сценарий из трёх файлов, начальные состояния, каждый вид завершения,
передача и одновременное завершение, передача закрытой задачи,
переоткрытие без ложного взятия, смена незавершённых статусов без взятия,
исчезновение и возвращение, повторные наблюдения, фильтр после передач,
конфликты входа и сохранность существующего выхода при ошибке.
