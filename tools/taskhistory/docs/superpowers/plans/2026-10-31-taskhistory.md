# Taskhistory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Сравнить снимки Jira и записать CSV с историей задач выбранных исполнителей.

**Architecture:** Независимая Python-тулза: `snapshots.py` проверяет входы,
`history.py` восстанавливает периоды, `cli.py` фильтрует результат и атомарно
пишет CSV. Все файлы тулзы внутри `tools/taskhistory/`.

**Tech Stack:** Python 3.9+, стандартная библиотека, unittest.

**Spec:** `../specs/2026-10-31-taskhistory-design.md`.

## Global Constraints

- Python 3.9+, без сторонних зависимостей и импортов других тулз.
- Дата снимка: `DD-MM-YYYY` в имени файла; дата блока — создание задачи.
- Взятие: смена инициалов; завершение: переход в `Отменен`, `Выполнен`, `Решен`.
- `--assignee` повторяется, фильтр применяется после восстановления истории.
- CSV: UTF-8 с BOM, `;`, 14 колонок из спецификации; выход обязателен.
- Исходные файлы и существующий выход сохраняются при ошибках проверки.

## Review Focus

- Символические и жёсткие ссылки выхода на вход: вход должен сохраниться.
- Повторное открытие и смена исполнителя одновременно: один новый период.
- Отсутствие в промежуточном снимке: завершение не выдумывается.
- Статус меняет только регистр или ё/е: нового события нет.
- Применение фильтра до сравнения: нельзя потерять предыдущего владельца.
