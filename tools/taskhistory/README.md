# taskhistory

Восстанавливает историю задач по нескольким текстовым снимкам Jira и пишет
CSV по исполнителям: какие задачи человек взял и какие завершил, на каких
снимках это стало видно. Фильтр позволяет оставить только нужные инициалы.

**Версия:** 0.1.0, источник — `taskhistory/__init__.py`, выводится по
`--version`. История — [CHANGELOG.md](CHANGELOG.md).

## Требования

Python 3.9+, только стандартная библиотека. Установка пакетов, сеть,
доступ к Jira и конфиг не нужны. Каталог тулзы самодостаточен.

## Запуск

Из каталога тулзы:

```sh
python3 -m taskhistory input-21-10-2026.txt input-28-10-2026.txt input-31-10-2026.txt \
    --assignee КМ --assignee АБ -o history.csv
```

Без фильтра — все исполнители:

```sh
python3 -m taskhistory /path/to/snapshots/input-*.txt -o history.csv
```

| Аргумент | Значение |
| --- | --- |
| `FILE ...` | Не менее двух снимков, порядок произвольный |
| `-o`, `--output` | Обязательный путь выходного CSV |
| `--assignee КМ` | Только этот исполнитель; повторите флаг для нескольких людей |
| `--assignee -` | Только задачи без исполнителя |
| `--version` | Версия тулзы |
| `--help` | Справка |

Регистр и пробелы по краям инициалов не учитываются. Без `--assignee`
показываются все люди. Если заданных инициалов нет в снимках, выдаётся
предупреждение; если нет ни одного совпадения, CSV содержит только заголовок.
Фильтр применяется после сравнения: передача от исключённого человека
выбранному исполнителю всё равно будет видна.

## Формат снимков

Имя файла содержит ровно одну дату `DD-MM-YYYY`, например
`input-28-10-2026.txt`. Даты в названиях каталогов не учитываются.
Снимки сортируются по дате, а не по порядку аргументов. Несколько снимков
одного дня не поддерживаются: без времени неизвестен их порядок.
Повторная подача того же файла через символическую или жёсткую ссылку
тоже считается ошибкой, даже если у ссылки в имени другая дата.
Отдельные файлы с одинаковым содержимым допустимы: состояние могло не измениться.

Содержимое — тот же формат шестистрочных блоков, что принимает vulnsheet.
Между блоками — пустая строка:

```text
Состоит из
TASK-101
CVE-2026-12345 vim
В работе
01.09.2026
КМ
```

Строки: служебная строка, ID задачи, CVE и компонент, статус, дата создания,
инициалы. Дата в блоке — **создание задачи**, она не используется как дата
взятия или завершения. Прочерк `-` или `—` в инициалах — «Без исполнителя».
Файлы должны быть в UTF-8; BOM, CRLF и пробелы по краям строк допускаются.

Поддерживаемые статусы: `В работу`, `В работе`, `Выполнен`, `Отменен`,
`Решен`. Регистр и `е`/`ё` не влияют на классификацию.

## Как определяется история

- **Взял:** инициалы человека появились вместо другого исполнителя или
  прочерка. Статус при этом может быть любым. Переход `В работу` →
  `В работе` при тех же инициалах не означает нового взятия.
- **Завершил:** статус перешёл из `В работу` или `В работе` в `Отменен`,
  `Выполнен` или `Решен`. Завершение относится к исполнителю текущего
  снимка. Смена одного завершённого статуса на другой не считается
  повторным завершением.
- **Дата события:** дата снимка, в котором изменение впервые замечено.
  Сам переход мог произойти раньше, между выгрузками.
- **Первое появление задачи:** прежние инициалы и статус неизвестны,
  поэтому даты взятия и завершения остаются пустыми. Дата наблюдения
  записывается отдельно, ограничение — в примечании. Это относится и к
  задаче, которая впервые появилась не в самом раннем снимке.
- **Передача:** прежнему исполнителю остаётся его период; новый получает
  отдельную строку и дату взятия. Если одновременно задача стала завершённой,
  завершение отражается у нового исполнителя, с пояснением о неизвестном
  порядке двух событий. Передача уже закрытой задачи не создаёт нового
  завершения. Снятие исполнителя не считается взятием кем-либо.
- **Повторное открытие:** новый период, прежнее завершение сохраняется.
  При неизменных инициалах нового взятия нет.
- **Исчезновение:** причина «Нет в снимке», без нового завершения.
  При возвращении создаётся новый период, исполнитель и статус сравниваются
  с последним известным состоянием до исчезновения. Разрыв указан в примечании.

События, произошедшие и отменившиеся между снимками, восстановить нельзя.

## CSV-отчёт

UTF-8 с BOM, разделитель `;`, строки сгруппированы по инициалам, затем
по ID задачи и номеру периода. Можно открыть в Excel или LibreOffice.

Одна строка — один период задачи у исполнителя. Передача, переоткрытие
или возвращение после отсутствия создают новый период. У одной задачи
может быть несколько строк у того же человека.

| Колонка | Смысл |
| --- | --- |
| `Исполнитель` | Инициалы или `Без исполнителя` |
| `Task ID`, `CVE ID`, `Компонент`, `Дата создания` | Последние наблюдавшиеся данные этого периода |
| `Период` | Порядковый номер периода задачи во всей истории |
| `Впервые у исполнителя (снимок)` | Начало наблюдения периода |
| `Взята в работу (снимок)` | Когда замечена смена инициалов на этого человека |
| `Завершена (снимок)` | Когда замечен переход в завершённый статус |
| `Последний статус` | Последний статус задачи в этом периоде |
| `Наблюдалась до (снимок)` | Последний снимок, в котором период ещё наблюдался |
| `Причина окончания периода` | Передача, переоткрытие, отсутствие или последний снимок |
| `История изменений` | Наблюдения и изменения с датами |
| `Примечание` | Неизвестные даты, разрыв наблюдений, одновременные изменения |

Даты в CSV — `DD.MM.YYYY`; неизвестные даты — пустые ячейки. Если передача
обнаружена 28 октября, а последний снимок с прежним исполнителем — 21 октября,
у прежнего периода «Наблюдалась до» = 21 октября, дата передачи в истории =
28 октября. Ранее установленная дата завершения сохраняется, даже если
позже задача исчезла из снимков или была передана.

## Ошибки и сохранность файлов

Некорректные даты имён, пустые файлы, битые блоки и неизвестные статусы
останавливают запуск. Диагностика содержит имя файла и, для блоков, его номер.
Полностью одинаковые блоки одного ID объединяются с предупреждением;
различающиеся блоки одного ID в одном снимке считаются конфликтом.
ID сравниваются без учёта регистра. Изменения CVE/компонента между снимками
не создают отдельную задачу: идентификатор истории — Task ID.

CSV записывается только после проверки всех входов и заменяется атомарно.
Выходом нельзя указать один из входов, в том числе через символическую
или жёсткую ссылку. Если выход — символическая ссылка на отдельный отчёт,
обновляется её цель; права существующего отчёта сохраняются.

Сообщения и краткая сводка идут в stderr. Успех — код `0`, ошибка — `2`.

## Пример и проверка

Три готовых снимка в [examples](examples/): две передачи от УА, одна от КМ,
затем завершения. Запуск из каталога тулзы:

```sh
python3 -m taskhistory examples/input-*.txt --assignee КМ --assignee АБ -o history.csv
```

Получатся четыре строки: АБ взял TASK-102 и TASK-103 28 октября, завершил
31 октября; КМ взял TASK-101 28 октября, завершил 31 октября, а TASK-103
уже был у него в первом снимке и затем передан АБ.
Готовый результат — [examples/history.csv](examples/history.csv).

Тесты без сети и сторонних библиотек:

```sh
python3 -m unittest discover -s tests -v
```
