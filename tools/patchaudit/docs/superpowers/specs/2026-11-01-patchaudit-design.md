# patchaudit

Утилита помогает при обновлении RPM: читает CVE-патчи текущей ветки
последнего билда пакета в Koji-теге и проверяет исправления Red Hat VEX.

## Вход и режимы

- `--package NAME`: показать, для каких патчей Red Hat уже выпустил фикс.
- `--nvr NAME-VERSION-RELEASE`: тот же поиск по имени, но NVR — целевая
  версия обновления, ей не обязательно существовать в Koji. Разделить
  патчи на доступные для удаления при таком обновлении и после следующего.
- Хаб Koji, тег, точная версия RHEL и GitLab — флагами или YAML-конфигом.
  Формат секций повторяет соответствующие секции vulnsheet; секреты в env.

## Подход

Самостоятельный Python 3.9+ пакет `tools/patchaudit`, без общих импортов
с соседними тулзами. Это единственный подход, соответствующий переносимости
тулз в CLAUDE.md. Копируются клиенты Koji, GitLab, HTTP, VEX, разбор source
URL, CVE и rpmvercmp из vulnsheet с их тестами; не копируются обработка
таблиц, NVD и AI. Vulnsheet не меняется.

## Поиск и решения

Последний билд запрашивается по имени пакета, затем берётся ветка из
`extra.source.original_url`. Читается актуальный PATCH этой ветки,
рекурсивно; коммит сборки не подменяет ветку. Если источник содержит только
коммит/SRPM или ветку определить нельзя, отчёт явно неполный.

CVE распознаются в именах файлов, включая несколько CVE одного года.
Каждая уникальная CVE запрашивается один раз; точная версия RHEL, stream,
бинарные aliases и выбор наиболее опасного статуса следуют vulnsheet.
JSON содержит все подходящие fixed NVR, даты vendor_fix и ссылки errata.
Для сравнения используются version и release по правилам RPM: NVR не
содержит эпоху. По уточнению пользователя SL соответствует EL: в целевом
release `sl` преобразуется в `el`, конечный `^<номер>` отбрасывается;
исходный NVR в JSON сохраняется. Другие disttag нельзя считать новее только
из-за буквенного disttag. При невозможности сравнения решение — review.

Решения по CVE: `remove` (Fixed и целевая версия включает фикс),
`remove_on_upgrade` (Fixed, но целевая версия старше), `fixed` (Fixed в
режиме имени), `keep` (уязвим/фикс не планируется/исследуется), `review`
(Not affected, нет записи/компонента/данных фикса, сбой, несравнимый release).
Для патча из нескольких CVE: remove/fixed только если все CVE допускают
его; keep побеждает, затем review, затем remove_on_upgrade.

## Выход и ошибки

UTF-8 JSON format=1: вход, последний билд, GitLab host/project/branch,
наличие PATCH, CVE с доказательствами, файлы патчей с решениями, summary,
problems, complete. Не-CVE файлы учитываются отдельным списком.
stdout по умолчанию, `-o` — атомарная запись. Лог — stderr.
Коды: 0 — проверка завершена; 1 — отчёт записан, часть источников недоступна
или ветка неизвестна; 2 — неверные аргументы/конфиг, недоступен хаб,
не удалось записать результат. Отсутствие PATCH и отсутствие CVE — нормальный
пустой результат; неизвестная ветка или проект — ошибка, а не пустой PATCH.
Тулза только рекомендует и не меняет репозитории/патчи.

## Проверки

Офлайн-тесты клиентов из vulnsheet; тесты двух режимов, backport release,
граничного равенства NVR, нескольких CVE в файле, разных RHEL/stream,
бинарных имён, отсутствия PATCH/ветки, ошибок VEX и JSON CLI. Реальный
прогон требует пользовательского хаба/конфига, которых в запросе нет.
